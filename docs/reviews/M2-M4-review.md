# M2–M4 independent review

Reviewed `develop` on 2026-11-16. Static review only: no build, tests, app, live server, or screen checks were run. Verdict: **not yet a reliable daily driver**. Counts: 0 critical, 9 major, 3 minor. Scenarios below are code-derived risks, not reproduced incidents. The prior M1 disposition was read; settled findings are not repeated.

## Feature verdicts

- **Transcript:** substantially improved: the production surface mounts TranscriptKit, loads older messages, saves anchors, coalesces stream updates and has bounded layout and image caches. However, every tail commit still scans/copies history (M3), some search/layout work is main-actor bound (M4), and supporting indexes grow without bounds (M7).
- **Terminal:** bounded scrollback and an emulator cache, explicit resize-before-buffered-input on reconnect, and real-server coverage are good foundations. Timing-dependent tests and unverified real keyboard/display behavior remain (m3); this review did not establish a separate high-confidence PTY correctness defect.
- **Navigation and notifications:** cached models, request-ID checks for notification actions, and Undo affordances are useful. Deferred deletion is not coordinated across windows or awaited at quit (M5). M1's draft and resync fixes were considered; no new high-confidence regression was established here.
- **Diff, Git and worktrees:** off-main Git execution, bounded output and conflict checks are good foundations, but file replacement is not atomic against concurrent editors (M1), and removal can destroy ignored files without warning (M2). Diff accessibility does not support navigating the whole document (M6).
- **Browser:** isolated agent content world, private-tab exclusion, host-side shared-tab checks, per-project stores and bounded tab/history policies are sound choices. Download access and lifetime still have gaps (M8, M9, m1). The review cannot establish real-site or hostile-page behavior without running WebKit.
- **Design system and integration:** semantic themes, disabled layout animation and native surfaces are constructive. Contrast, responder routing, assistive technology and perceived responsiveness still require human acceptance.

## Findings

### Major

**M1 — Revert can overwrite an edit made after its preflight check.** Engineering 8 and UX 3; artifact safety. `Sources/Engine/Git/WorkingCopy.swift:91` checks *all* snapshots before writing any, then :95–100 writes and, on failure, rolls back without checking again. An editor or agent saving a file after the check but before its write loses that edit; a concurrent edit to an already-written file can also be overwritten by rollback. This contradicts the safety claim at :44–46 and the feature note's all-or-nothing claim. Use a coordinated file-access strategy with a version check immediately at replacement and conflict-aware rollback; where external writers cannot be serialized, state that limitation and retain recoverable originals. Test controlled writes between preflight, replacement and rollback.

**M2 — Removing a seemingly clean worktree deletes ignored user files.** UX 3 and artifact safety. `Sources/Engine/Git/WorktreeService.swift:253` checks `git status --untracked-files=all`, which omits ignored files, then :259 removes the directory; `Sources/BelloCodeApp/Content/ChangesSurface.swift:173` offers Undo for the apparently clean case, but restore recreates only the checkout (`WorktreeService.swift:270`). A worktree containing an ignored `.env`, local database, or generated but valuable asset is removed without confirmation and Undo cannot restore it. Detect ignored contents and explicitly warn that they cannot be restored, or preserve the directory in a recoverable trash location before removal; test ignored files and Undo.

**M3 — Every streaming update traverses and copies the transcript history on the main actor.** Engineering 2, 4, 7; research 01 A.1. `Sources/TranscriptKit/Transcript/Controller/TranscriptController.swift:368` finds the last turn, :377–379 scans and copies the history prefix, and :437–454 compares all preceding rows; :462 rebuilds the full index when a row changes. With a long conversation, each 33 ms tail commit repeats O(history) main-thread work, risking typing and scroll hitches even though only one tail row changes. Keep indexed turn boundaries and update only the affected range and index entries; measure main-thread work as history grows while streaming. This qualifies the note's narrow-update claim, even though table row reloads themselves are selective.

**M4 — Find can synchronously parse and lay out large rows on the UI thread.** Engineering 7; UX 1. `Sources/TranscriptKit/Transcript/Controller/TranscriptController+Find.swift:170` parses up to 64 stale rows synchronously at :175–177; revealing a match at :114–117 calls `LayoutEngine.layoutNow` on the main actor. A search over a few very large messages, or jumping to an uncached long result, can freeze input despite the note's off-main parsing claim. Always build stale index entries and missing layouts off-main, then check query, row revision and generation before applying; test a large single row and cancellation on thread switch.

**M5 — Deferred deletes race other windows and app shutdown.** Engineering 8–9; UX 3, 8. `Sources/BelloCodeApp/Shell/WorkspaceController+Organisation.swift:118` hides a deleted thread only in its originating window; another window can still edit or send to it during the five-second delay. At close, :141–159 launches unowned delete tasks, while `Sources/BelloCodeApp/Launch/AppDelegate.swift:94` closes windows and immediately starts `runtime.stop()` at :96. The server may stop before deletes complete, and failures after window teardown have nowhere visible to report. A user can see “Deleted,” quit, and find the thread still present, or lose work started in another window. Centralize pending deletion and visibility across windows, disallow conflicting operations, and await outcomes before stopping the engine; persist or surface failures. Test two windows and quit with a blocked delete.

**M6 — VoiceOver cannot traverse the complete diff or operate its drawn controls.** UX accessibility; research 03 C and E. `Sources/DiffKit/View/DiffContentView.swift:729` exposes only currently visible rows, capped at 121, as newly created static-text elements. Offscreen rows have no accessibility children or scroll-to-element contract; gap expansion and hunk revert controls drawn in the view are not accessible actions on those elements. A VoiceOver user navigating beyond the visible rows cannot reliably read the rest or activate these controls. Provide stable, navigable virtual accessibility elements with scroll-to-visible and actionable gap/hunk elements, or an accessible text representation; test long diffs and actions with VoiceOver. The feature note's “accessibility rows” exists, but does not establish full document access.

**M7 — Transcript auxiliary caches are unbounded across image-heavy use.** Engineering 5. `Sources/TranscriptKit/Transcript/Controller/TranscriptController+Find.swift:220` accumulates `imageRows`, :222 records requests, and :247 stores sizes; failed requests remain in `imageRequests` at :235–236. `unbindSource()` (`TranscriptController.swift:250–280`) cancels tasks but does not clear these structures. Switching through threads containing many distinct images or failed URLs grows metadata for the lifetime of the controller, and revisiting a failed URL cannot retry. Bound and evict metadata together with image entries, clear per-source associations on unbind, and permit bounded retries. Test repeated thread switches and failed loads.

**M8 — Download retrieval trusts a stale size and reads arbitrary replacement bytes on the main actor.** Engineering 5, 7; browser privacy. `Sources/BrowserKit/Browser/BrowserOperations.swift:116–127` checks the recorded download size, then synchronously reads its destination. After a small shared-tab download finishes, another process or the user can replace or enlarge that path before the agent calls `files.get`: the app returns the replacement, potentially sensitive, file to the agent and can allocate far more than the promised 5 MiB while blocking the UI. Open and verify the actual file identity and size at retrieval, read with a hard byte limit off-main, and refuse changed files; test replacement, symlinks, growth and cancellation.

**M9 — Browser download admission is not bounded.** Engineering 5. `Sources/BrowserKit/Browser/BrowserDownloads.swift:53–73` retains every running download and removes only finished entries when a new download arrives. A page that initiates many downloads can grow the list and simultaneous network/disk activity indefinitely; completed entries can also stay over the limit until another download starts. Enforce a hard active-download admission cap with visible cancellation/refusal and trim finished entries on completion; test a burst of concurrent downloads. This contradicts the documented bounded-list claim.

### Minor

**m1 — WebKit download progress assumes its callback is already on the main actor.** Engineering 7. `Sources/BrowserKit/Browser/BrowserDownloads.swift:56–64` invokes `MainActor.assumeIsolated` inside a KVO callback, without dispatching to the main actor. KVO delivers on the posting thread; an off-main progress update can violate the isolation precondition and crash. Capture the Sendable progress values and explicitly hop to `MainActor`; verify with an off-main KVO delivery.

**m2 — Transcript accessibility does not offer normal text navigation within a message.** UX accessibility; research 03 E. `Sources/TranscriptKit/Transcript/Views/TranscriptTableView.swift:232` exposes each entire drawn row as static text, and `TranscriptController+Find.swift:303–307` supplies its value, but no character/range accessibility interface. A VoiceOver user cannot navigate a long reply by character, word or line or select a precise passage using standard text commands. Expose a text accessibility interface or accessible backing text view with range/selection support. This limitation is acknowledged in the feature note and still affects daily use.

**m3 — Timing-based tests leave lifecycle races uncertain.** Engineering 8–9; research 03 E. `Tests/TerminalKitTests/TerminalSurfaceTests.swift:219` and :227–231 depend on fixed 50–100 ms sleeps; `Tests/BelloCodeAppTests/NavigationWindowTests.swift:144` uses 300 ms. A slow machine may fail spuriously, while a fast mock can pass without exercising shutdown, real WebKit, or PTY ordering races. Replace sleeps with explicit barriers/observable milestones and add targeted real-service or injected-delay tests for the scenarios above. Existing real-binary tests are useful evidence but do not establish screen behavior.

## Five changes that would most improve feel

1. Make tail updates independent of transcript length, and measure typing and scrolling while streaming (M3).
2. Coordinate deferred deletes across windows and make quit wait for their results (M5).
3. Move find parsing and uncached layout off the UI thread with cancellation (M4).
4. Make revert and worktree removal preserve concurrent and ignored user files (M1–M2).
5. Give VoiceOver complete diff navigation and real text navigation in replies (M6, m2).

## Human checks and limits

- Run the complete acceptance checklist in `docs/research/03-ux-patterns.md` section E at the screen; none of its visual or interaction claims is certified by this review.
- Measure unlocked on-screen frame pacing and input latency while streaming, fast scrolling, resizing, searching and switching long threads; verify anchor preservation and follow/release/rejoin with a trackpad.
- Exercise IME composition, dead keys, undo, focus restoration, first-responder menu validation and shortcut conflicts in composer, terminal, browser and diff; exercise vim/tmux and resize/reconnect ordering with real PTYs.
- Use VoiceOver and Full Keyboard Access through long transcript and diff content, actions, approvals, terminal and browser; check contrast, text sizes, appearance, Reduce Motion, multiple displays and windows.
- Check real-site sign-in, private browsing, prompts, uploads/downloads, popups, hostile pages, browser sharing and agent takeover; verify OS permission and notification delivery in a signed app.
- Exercise revert, Undo, worktree cleanup, cross-window deletion and quit against disposable repositories containing concurrent edits, ignored files and active sessions. Check navigation and relaunch restoration with network gaps and real server restarts.
- Follow up with deterministic tests and instrumented real-server/browser checks; this review did not run existing tests or independently verify feature-note benchmark numbers.

## Disposition

Work package M2-E (review fixes, round two), branch `t3/review-round-two-fixes`; M3, M4, M7 and m2 by M2-F
(transcript review findings), branch `t3/transcript-review-findings`. Each finding was checked against the
code first and reproduced with a deterministic test where feasible; the tests stay as regression tests. No database
migration was added.

| **M1** revert vs concurrent edits | **Fixed** (2fb81f9). Reproduced: six `RevertAtomicityTests` inject a write, atomic save, create or edit between the preflight check and the replacement through a `WorkingCopy` test seam; five failed before the fix. Each file is now replaced by a compare-and-swap (`renamex_np` `RENAME_SWAP`/`RENAME_EXCL`, then a comparison of the bytes swapped out; a mismatch swaps back and fails with `changedOnDisk`, file untouched). Rollback and Undo use the same check (exact bytes and permissions, or refuse). Residual limit, documented: a writer still holding the old file open and writing in the microseconds between swap and comparison cannot be serialized without its cooperation. |
| **M2** worktree removal and ignored files | **Fixed** (e64ab56). Reproduced: an ignored `.env` and `build/` made `git status` report clean. `WorktreeService.contents` counts uncommitted, untracked and ignored files; such a worktree needs confirmation (`filesAtRisk`, naming up to five paths) and its files are moved to the Trash before `git worktree remove`; Undo re-checks out and moves them back (staged changes return unstaged; an emptied Trash is reported). Tests use an injected holding folder, never the real Trash. |
| **M3** tail commits scan history | **Fixed** (4a75865, package M2-F, branch `t3/transcript-review-findings`). Still held after M2-B: `sync()` scanned rows from the top for the last turn and copied the prefix, `apply()` compared every row and rebuilt the row index. Measured in process (`TranscriptDemo --scenario stream-cost`, release, MockOpenCode `.large`, 150 deltas/s for 12 s, 373 tail commits each): main-thread CPU per commit p50 0.94 / 3.59 / 5.52 ms at 1,000 / 5,000 / 10,000 messages before, 0.22 / 0.47 / 0.44 ms after; rows touched per commit 7,832 / 38,932 / 77,902 before, 7 at every size after. The last turn's rows are found from the end, replaced in place, diffed and re-indexed alone. Guard: `StreamingCostTests` (row work and storage identity, equality with a full rebuild). Remaining per-commit cost scales with the streaming reply (`contains("![")` on its text), not the history. A new message in the list still revalidates untracked messages (O(history) lookups, once per message, not per delta). |
| **M4** find parses and lays out on main | **Fixed** in part, part no longer applicable. The synchronous parse of up to 64 stale rows was already gone (M2-B builds the index off-main). Now both run off-main and the reveal applies only if the binding generation, row version and layout key are unchanged and no newer reveal started (d3d773f). Guards: `FindRevealTests` (0 main-thread parses and synchronous layouts; dropped on thread switch). A streaming row without a composed tail layout still lays out synchronously (counted; rare). |
| **M5** deferred deletes vs windows and quit | **Fixed** (b6731c5). Confirmed by reading: `hiddenThreads`/`pendingDeletes` were per window and quit did not await deletes. `PendingThreadDeletions` (one per engine) hides rows in every window, moves windows off the thread, offers Undo in every window (any restores everywhere), sends each delete once, commits when the last window closes, and quit awaits results before stopping the engine (quit alert for failures no window can show). Tests: two fake windows, a blocked send during quit, exactly-once sends, plus a two-window shell test against MockOpenCode. |
| **M6** diff VoiceOver | **Fixed** (122d8d0). Every row is a virtual accessibility element (ranged children API, bounded on-demand cache, computed frames, focus scrolls into view) with actions for Revert Hunk, Show 20 More / Show All Lines, Add Comment and file toggle; results are announced once. Verified through the accessibility API in process only; VoiceOver itself (VO navigation using the ranged API, rotor, speech) was not run. |
| **M7** transcript auxiliary caches | **Fixed** (224da02). Reproduced: after 30 image threads (180 sources, 12 decoded), rows were kept for all 180 sources and sizes for 150; failed or switch-cancelled loads stayed requested, so a revisit never retried. Now `imageRows` holds in-flight loads only (cleared on unbind), failures retry with backoff (5 s doubling, 3 attempts) and on rebind, capped at 256 per binding, and remembered sizes are LRU-bounded (2,048, decoded images kept). Guard: `ImageMetadataTests`. |
| **M8** download retrieval | **Fixed** (78e541e). Identity (device, inode, size, mtime) is recorded at completion; `files.get` reads off-main on an `O_NOFOLLOW` descriptor, re-checks before and after a 5 MiB-capped cancellable read, and refuses changed files (`file_changed`). Tests: replacement, growth, symbolic link, oversize, removal, cancellation. |
| **M9** download admission | **Fixed** (78e541e). 3 running, 7 queued (destination withheld until a slot frees), the rest refused; Queued and Refused shown in the shelf; ended entries trimmed on completion. Test: a burst of 30, promotion and queued cancellation. |
| **m1** KVO progress actor assumption | **Fixed** (78e541e). Values are read on the posting thread and applied in a `MainActor` task from a nonisolated handler. Test posts progress from a background thread. |
| **m2** transcript text navigation | **Fixed** (b34f0ff). Each row's static-text element implements the NSAccessibility text interface (characters, string/attributed string for range, line for index, range for line, bounds for range, range for point, style and composed-character ranges, visible range, selected text and settable selected range = the transcript selection), from the row's blocks and layout lines, built on demand per live cell; off-screen rows are not materialised.
