## 3. GR3-01 · blocker · Auto: `uniq - FILE` and `xxd - FILE` are allowed as read-only and write the file

**Where:** [RiskPolicy.swift:788](../../Sources/Engine/Auto/RiskPolicy.swift#L788) and
[:791](../../Sources/Engine/Auto/RiskPolicy.swift#L791) in `writingReadOnlyUse` decide that `uniq` and `xxd` write only
when two words that do not start with `-` follow the program. `-` starts with `-`, so it is not counted, although both
programs read it as "standard input" and take the next word as the output file. Nothing else looks at the output
operand: `mayWrite` is false for a read-only program ([:737](../../Sources/Engine/Auto/RiskPolicy.swift#L737)), so the
path is not examined as a write, and `readOnlyShell` ([:1079](../../Sources/Engine/Auto/RiskPolicy.swift#L1079)) finds
no writing use.

| Line, in a thread set to Auto | The policy | What runs |
| --- | --- | --- |
| `uniq - opencode.json` | `ALLOW(read_only_command)` | empties the agent's configuration file |
| `uniq - .git/config` | the same | empties the repository's configuration |
| `printf '<text>' \| uniq - .git/config` | the same | writes `<text>` into the repository's configuration |
| `printf 'hello' \| xxd - .git/config` | the same | replaces the file's content with a hexdump; `xxd -pr - FILE` and `xxd -p - FILE` alike |

**Evidence.**

- The decisions come from the repository's `RiskPolicy.swift`, `ShellAnalysis.swift` and `OptionSyntax.swift`, copied
  byte for byte into the scratch folder (only `import BelloCore` removed, its two types stubbed word for word) and
  compiled; `RiskPolicy.decide` was called on each line with a scratch project holding `.git/config`, a hook and
  `opencode.json`. The same lines spelled as the fix lists them are refused: `uniq x.txt opencode.json` and
  `printf 'x\n' | xxd -r - .git/config` escalate.
- `uniq`: BSD `uniq` on macOS and GNU coreutils 9.1 in `node:22-bookworm-slim`, the base of the workspace image, both
  replaced the second operand's content; `uniq -- - FILE` as well.
- `xxd`: macOS's build (2025-08-24) wrote the file. It is not in the default workspace image, so this half needs a
  project image or a dev container that has vim's `xxd`. Alpine's busybox `xxd` takes one operand and refused the command.
- End to end, in scratch: the two lines above ran in the workspace image's base container against a repository bind-mounted
  read-write, as the workspace mounts a project ([WorkspaceSpec.swift:221](../../Sources/ContainerKit/Workspace/WorkspaceSpec.swift#L221));
  the exec helper adds no guard of its own ([bellocode-exec/main.swift](../../Sources/bellocode-exec/main.swift)). The
  configuration written was `core.fsmonitor = sh -c "<one command that writes a file>"`. `git status`, run afterwards on
  the Mac with plain git, created that file from a process on Darwin.
- BelloCode's own git is not the way in: it forces `core.fsmonitor` off ([HostGit.swift:124](../../Sources/ContainerKit/HostGit/HostGit.swift#L124))
  and its hostile-repository probe already writes this configuration "as a process in the container would"
  ([HostGitProbe.swift:52](../../Sources/Engine/Git/HostGitProbe.swift#L52)). The developer's terminal and IDE run git without that.
- No test covers an output operand behind `-`: [RiskPolicyTests.swift:313](../../Tests/EngineTests/RiskPolicyTests.swift#L313)
  has `uniq src/main.swift out.txt`, [:471](../../Tests/EngineTests/RiskPolicyTests.swift#L471) has `xxd -revert x y`.

**Origin.** Not introduced by this round. The operand counts of both rules are unchanged in `7974d8d`'s diff (only
how `xxd -r` is matched changed); they predate it, as GW02 did.

**Why a blocker.** By the standard this release sets itself: GW02 (b), `printf … | sort --out=.git/config`, was held for
the same reason, and writing `.git/config` or a hook by any program is a mandatory escalation
([auto-mode.md:52-54](../features/auto-mode.md#L52)), while a read-only command is allowed "never with an option that …
writes a file" ([:61-68](../features/auto-mode.md#L61)). Here no approval card appears and the audit records
`read_only_command`, for a command that changes what the developer's own git runs. Auto is opt-in per thread; that
bounds who is exposed, not what the policy promises.

**Fix.** The same as recommended for GW02: decide that a program is read-only from the operands and options the policy
knows, not from those it forbids. At least, count `-` as an operand of `uniq` and `xxd`, so any second operand is a
writing use. Add the four lines above to the N05 regression list and bump the policy version.

## 4. New blockers in the round-3 and round-4 diffs (`ae8071b..e6b84a6`)

**R3-01 (Astra), data loss: confirmed at `e6b84a6`; closed at `705d749` by R4b.** I reproduced it against the
repository's `ComposerController` and `ComposerHost` at `e6b84a6`, with two hosts over one stored draft, as two windows

[Engine.swift:412](../../Sources/Engine/Presentation/Engine.swift#L412)). With "hello world" and an attachment typed

merges the prompt into the other composer's own copy and saves that, and a composer never re-reads a draft changed
elsewhere ([:170](../../Sources/ComposerKit/Host/ComposerController.swift#L170)). It needs the same thread in two
windows and no later edit in the active one. Section 5 has the tip.

**No other blocker found.** Read in full: `Plugin/src/pins.ts`, the pin lookup in [Plugin/server.ts:210](../../Plugin/server.ts#L210),
`sessionCheckout` and `instructionLookup` in [Plugin/src/project.ts](../../Plugin/src/project.ts), the pin folder's

- **Pins (AF08).** The pin folder is `~/Library/Application Support/BelloCode/opencode/bellocode-instruction-pins`
  ([OpenCodeIsolation.swift:38](../../Sources/OpenCodeKit/Server/OpenCodeIsolation.swift#L38)): inside the path Auto
  refuses to write, outside every code root and mount. A lookup is refused unless the pinned folder is the very folder,
  by device and inode, before and after the reads; a checkout replaced by a link or by another folder is refused; an
  unpinned session old enough to have lost its pin is served only on a path with no link in it. Every failed open,
  read or write gives no instructions. The plugin's 101 tests pass on macOS from a scratch copy (bun 1.3.14), which runs
  the `O_NOFOLLOW_ANY` branch that the container-based suite never reaches; nine hostile-input cases of mine pass too:
  17 malformed pin files, a pin that is a folder, 8 path-shaped session IDs (nothing written outside the store), a
  linked store, a wrong-typed watermark folder, overflow, a swapped or linked checkout, a hard-linked `AGENTS.md`
  (refused, nothing handed over).
- **Dockerfile reader (GW01).** Section 1. The instrumenter that shares the rule ([ImageBuildNetwork.swift:91](../../Sources/ContainerKit/Network/ImageBuildNetwork.swift#L91))
  leaves the original text intact and instruments one stage per `FROM` the reader sees, on 19 of 20 sample files; the
  twentieth is in section 7.
- **Host git (AV03).** Each `.git` is opened once without following a link; its type, a `.git` file's text and every
  granted path come from those descriptors; the back-reference is compared by identity. Every failed step returns
  nothing, and the sandbox then refuses the write.
- **Rewind (AF19).** No history, a message not found, or no assistant message after it exempts no child, so the rewind
  is refused rather than allowed. A child of an earlier turn is created before the first assistant message of the
  rewound turn, and the comparison is strict.
- **Secrets (AF26, AV13).** A superseded replacement is released by the newer one's answer or when nothing is queued;

  equality is the synthesized one, over every stored property.
- **Egress (AV2-04), Shared Chrome (AV05, AV11).** The proxy only adds checks: a withdrawn scope ends the connection
  and dispatch is judged under the registration lock. The browser client registers and sends in one step, refuses an ID
  that was cancelled or timed out before, and ignores a response ID that is not an integer in range.
- **GitLab (AV2-03, AV2-05, AV2-07, AV2-01).** Each number from the server is checked before `Int(_:)`; the 429 wait is
  bounded to an hour and the backoff exponent to 32; a wake that cannot be redacted is held, one saved by an earlier
  version is rebuilt, never posted.

## 7. Known limitations

- A program named by its path is judged by its basename: it is allowed as read-only when an executable named like a
  read-only program already exists at that path (candidate 2 above).
- rg takes `--pre` from `RIPGREP_CONFIG_PATH`; only the rule that an assignment on the line is never read-only stands
  between that and a deterministic allow (candidate 3 above).
- Reads, not writes, which the stated criterion leaves out: a committed secret is allowed through an object name
  (`git show HEAD:.env`, `git cat-file -p HEAD:.env`) while `cat .env` escalates; `cat .git/config` and `git remote -v`
  are allowed and a remote URL can carry a token.
- The build instrumenter finds heredocs textually: a quoted `<<WORD` in a `RUN` line made it skip the rest of one sample
  file, so a later stage got no trust roots. The image policy does not depend on it, and the rule predates this round.
- Pins: a session older than the store, or one that lost its pin, gets no repository instructions when its recorded
  folder is not exactly its canonical path (a link above the checkout, a name that differs in case or normalization).
  A pin folder that cannot be written, on a full disk for instance, gives every session none. Both fail closed.
- The policy version stayed `bellocode-auto-5` through `84b6543` and `95268f0`, although both changed lists that the
  audit's version is meant to distinguish.
