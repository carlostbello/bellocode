## 1. The five fixes

### GF02 · Verified

[server.ts:875-882](../../Plugin/server.ts#L875): a held target forces `delivery` to `"queue"` and adds `resume: false`.

That `resume: false` admits without waking was checked in the pinned binary rather than assumed. The plugin host's
`session.prompt` is the internal session service's `prompt` (`prompt:se.prompt`), which hands the whole input to the
per-session prompt service. The HTTP route `session.prompt` calls that same function, and it admits the input and then
runs `if(Ze.resume!==!1) yield*y.wake(ue)`. So the call the plugin makes and the call the real-binary test makes are
one function.

- [auto.test.ts:224-248](../../Plugin/test/auto.test.ts#L224): asserts `resume === false` for a held target and that
  `resume` is absent otherwise. The first assertion fails on the old code.
- [AutoHookRealBinaryTests.swift:406-418](../../Tests/EngineTests/AutoHookRealBinaryTests.swift#L406): a prompt with
  `delivery: .queue, resume: false` on an idle session stays in the inbox, produces no message and leaves `time.busy`

Not covered: no real-binary test drives `thread_send` through the plugin into a held thread and then Resume; that link
is by reading the binary. The negative assertions also have no positive control in the same sandbox (a default-resume
prompt proving a wake leaves `time.busy` set there), which would make them airtight.

## 2. New findings

### GV01 · major · Docker accepts instructions that begin with a form feed, vertical tab or NEL; the image policy's reader does not see them

**Where:** [DockerfileBases.swift:160](../../Sources/ContainerKit/Workspace/DockerfileBases.swift#L160),
[:210](../../Sources/ContainerKit/Workspace/DockerfileBases.swift#L210), [:222](../../Sources/ContainerKit/Workspace/DockerfileBases.swift#L222),
[:227](../../Sources/ContainerKit/Workspace/DockerfileBases.swift#L227) (leading trim with `.whitespaces`) and
[:68-70](../../Sources/ContainerKit/Workspace/DockerfileBases.swift#L68) (words split on space and tab); called from
[DockerFilterPolicy.swift:765-776](../../Sources/ContainerKit/DockerFilter/DockerFilterPolicy.swift#L765) (`buildBaseRefusal`, R14) and
[DevContainers.swift:209-215](../../Sources/Engine/Containers/DevContainers.swift#L209).

**Problem.** Docker's parser is BuildKit's `frontend/dockerfile/parser`, used by the BuildKit frontend and by the
classic builder that the filtered `/build` route forces (`DOCKER_BUILDKIT=0`). It strips leading whitespace with Go's
`unicode.IsSpace` before it looks for `#` or an instruction; that set includes U+000B, U+000C and U+0085. Its `FROM`
parser splits on `[\t\v\f\r ]`. Swift's `CharacterSet.whitespaces` is space, tab and category Zs, so those three stay.
For a line `\u{000C}FROM image`, BelloCode's keyword is `"\u{000C}FROM"`, no case matches, and the image is not
returned. `images(in:)` then gives the policy nothing to refuse.

Two consequences:

1. A base image outside the policy (allowlist, `requireDigest`, `requireSignature`, `pullPolicy`) is pulled and built.
2. A parser directive is hidden the same way: `\u{000C}# escape=\`` as the first line. Docker then uses backtick as
   the escape token, BelloCode keeps `\` and joins lines Docker does not, so a later `FROM` can sit inside what
   BelloCode reads as a continuation (`RUN true #\` followed by `FROM <image>`).

**Scenario.** A managed deployment with an allowlist. A repository opened in BelloCode has a dev container whose
Dockerfile contains `\u{000C}FROM <image not on the allowlist>`. The person enables the dev container. The check at
`DevContainers.swift:210` finds nothing to refuse, the image is pulled and its `RUN` steps execute. The same Dockerfile
built by an agent through the workspace's Docker endpoint passes `buildBaseRefusal`. The owner's answer on images
(`docs/PLAN.md` §0) is that the allowlist applies to base images, which is exactly where this defeats it.

**Origin.** Pre-existing: the previous reader used the same trim. AF11 rewrote it to read lines "as BuildKit reads
them" and closed CRLF and combining marks, not this. The consequence is the one Astra recorded against AF11 for a
byte-order mark, where its status is Incomplete, major.

**Evidence.** Read, not run: BuildKit `frontend/dockerfile/parser/parser.go` on `master` and `v0.12.5`
(`trimLeadingWhitespace`, `isComment`, `processLine`, `reWhitespace`), and moby `v26.1.4` `builder/dockerfile/builder.go`
(which imports that parser and honours `EscapeToken`).
[DockerfileBasesTests.swift:92-100](../../Tests/ContainerKitTests/DockerfileBasesTests.swift#L92) has no such case.

**Fix.** Trim Go's set (`\t\n\v\f\r `, U+0085 and Zs) at the four sites and split words on `[\t\v\f\r ]`. More robustly,
refuse the build whenever the reading is not certain: a line or word holding a control character other than tab, CR or
LF. Add tests with U+000B, U+000C and U+0085 before `FROM` and before `# escape=`.

### GV02 · minor · GF11: the slot is handed on before the 429 is recorded, so the first waiter still passes

**Where:** [GitLabProvider.swift:249](../../Sources/Engine/Extras/Forge/GitLabProvider.swift#L249) (`release`) and
[:273-276](../../Sources/Engine/Extras/Forge/GitLabProvider.swift#L273) (`throttle`).

**Problem.** On a 429, `response` releases the slot first and records the throttle after the status switch. `release`
resumes the first waiter, whose re-check is queued on the gate actor before the `throttle` call is.

**Scenario.** Four requests in flight, six waiting; one gets a 429. The waiter it wakes passes the check and is sent
inside the window, and its own 429 would add a strike. The fix reduced "three waiters, possibly five in flight" to one
waiter; the promise that the whole instance waits after a 429 still does not hold for that one.

**Fix.** Record the throttle before releasing (or throttle and release in one actor operation) and add a provider-level
test with a queued caller; `ForgeGateTests` calls `throttle` before `release` itself, so it cannot see this. This is
AV14 in the Astra report, same lines.

### GV03 · minor · AF14: a grep operand the preflight cannot resolve is skipped without a finding

**Where:** [RiskPolicy.swift:157-162](../../Sources/Engine/Auto/RiskPolicy.swift#L157) and
[:261](../../Sources/Engine/Auto/RiskPolicy.swift#L261); [ShellAnalysis.swift:319-328](../../Sources/Engine/Auto/ShellAnalysis.swift#L319).

**Problem.** The preflight now escalates on an unquoted `$` and expands `*`, `?` and `[` with `glob(3)`. Brace
expansion is neither flagged nor expanded: `{` only marks a command group at the start of a word, and never sets
`hasGlob`. `{app,secrets}` reaches the preflight as one literal word, `stat` on that path fails, and the root is
skipped with no finding. An option value the shell globs is read the same way: with `.github/` present,
`--exclude-dir=.g*t` becomes `.github` for grep and leaves `.git` searched, while the preflight matches the literal
pattern against `.git` and treats it as excluded.

**Scenario.** Auto mode, a workspace whose shell is bash (RHEL-family images, or a dev container that sets it):
`grep -r x {.,secrets}` is allowed without asking and reads `secrets/id_rsa`.

**Origin.** Pre-existing; AF14 closed `.git`, `node_modules`, links, globs and variables.

**Fix.** Flag `{` in an argument as opaque, and escalate when a root cannot be resolved or an option value contains
glob characters.

### GV04 · minor · A thread's environment replacement is not sequenced, so a stale one can win after a revocation

**Where:** [SecretManager.swift:855-869](../../Sources/Engine/Secrets/SecretManager.swift#L855).

**Problem.** `applyEnvironment` computes the variables, then sends them; nothing orders two calls for the same session.
If a call that read the grants before a revocation lands after the revocation's own replacement, the server keeps the
old variables, and that late success removes the session from `pendingEnvironmentSessions`, so nothing retries it.

**Scenario.** Visible mode. The reconnect loop is replacing session S's environment (it has read the value) while the
person revokes the secret. The loop's request completes after the revocation's. `echo $NAME` in S still prints the
value until the next reconnect or restart, and Settings shows nothing pending. For placeholder mode the leftover marker
is refused by the proxy, so only visible mode leaks.

**Origin.** The ordering is older; AF26 rewrote the function for retries without adding one (AGENTS.md rule 8).

**Fix.** Keep a per-session generation, capture it before computing, and skip the send (and keep the session pending)
when a newer application has started.

### GV05 · minor · Three older refusals never give back the uses a request reserved

**Where:** [EgressProxy.swift:621-630](../../Sources/SecretKit/EgressProxy.swift#L621), [:635-639](../../Sources/SecretKit/EgressProxy.swift#L635),
[:650-660](../../Sources/SecretKit/EgressProxy.swift#L650).

**Problem.** The ledger's contract is that "only a request refused before anything was sent releases its reservation".
AF15 added `ledger.release(uses)` on its new path ([:671](../../Sources/SecretKit/EgressProxy.swift#L671)). Three
older exits that refuse before sending still do not: the durable record failing after a successful reserve, the
upgrade refusal, and a failed upstream connection. For a limited binding each burns one use; the agent can repeat
upgrade requests with its own placeholder to exhaust it.

**Origin.** Pre-existing. AV13 in the Astra report covers the durable half (a refused use that survives a relaunch);
this is the in-memory half on other paths.

**Fix.** Release on every exit before `wire.send`, or move `reserve` after the connection is open.

### GV06 · minor · The context copy holds two descriptors per folder level with no depth bound

**Where:** [DevContainerContext.swift:281-303](../../Sources/ContainerKit/Workspace/DevContainerContext.swift#L281).

**Problem.** `copyFolder` recurses and keeps `child` and `childTarget` open per level. Nothing in `Sources` raises the
soft limit on open files, and launchd's default for a GUI app is 256 (`launchctl limit maxfiles`). With the app's other
descriptors, a context nested about a hundred folders deep fails with EMFILE, which the code reports as "its build
context changed while it was being copied". The previous iterative walk had no such limit.

Related: a subfolder the user cannot read used to be skipped and now fails the whole copy with the same message.

**Scenario.** A context that includes a pnpm store (`node_modules/.pnpm/…/node_modules/…`) builds before this change
and is refused after it, with a message that sends the person looking for a race.

**Fix.** Raise `RLIMIT_NOFILE` at launch (the usual practice for GUI apps), bound the depth with its own message, and
give an unreadable folder its own message.

### GV07 · minor · A trust change reloads at most 64 locations and does not say when there are more

**Where:** [OpenCodeConfigService.swift:189-197](../../Sources/Engine/OpenCodeConfig/OpenCodeConfigService.swift#L189), used at [:178](../../Sources/Engine/OpenCodeConfig/OpenCodeConfigService.swift#L178).

**Problem.** AF17 reloads every active location a trust entry covers. `covered(by:among:)` stops at 64 and returns no
sign of truncation. The rest are neither reloaded nor added to `unacknowledged`, so `trustPending` clears and Settings
reports the change applied. After a revocation, agents and skills from that repository stay registered in those
locations until their next reload or restart. Commands are not affected: they re-read the trust file at invocation.

**Scenario.** More than 64 distinct project or thread directories under one trusted root (a monorepo opened folder by
folder) and the person revokes trust in the root.

**Fix.** Put the remainder into `unacknowledged`, or report "N more locations apply at their next run" (AGENTS.md rule
5: overflow is visible, never silent).

### GV08 · minor · GF02: a `thread_send` during an in-flight interrupt still wakes the target

**Where:** [server.ts:869-882](../../Plugin/server.ts#L869) reads the hold; [:953-969](../../Plugin/server.ts#L953) writes it after `cascadeStop`.

**Problem.** The hold is written only after the stop is confirmed (up to 5 s when a child is slow to settle). A send
that reads the target inside that window sees no hold and is admitted with the default resume. The target, just
interrupted and idle, starts a run; the hold is then written either over a running thread or just before the run-start
event clears it.

**Scenario.** Thread A interrupts C, which has a child. Before the confirmation finishes, thread B sends to C. C runs
with its parked queue, and A's tool result still says the queued work is held.

**Fix.** In `thread_send`, if `interrupting.has(target.id)`, await it and read the target again; or write the hold
before `cascadeStop`.

### GV09 · minor · The trust store is no longer rebuilt in the image; two bundle files are mounted instead

**Where:** [CorporateNetwork.swift:109-116](../../Sources/ContainerKit/Network/CorporateNetwork.swift#L109), mounted at [WorkspaceSpec.swift:230](../../Sources/ContainerKit/Workspace/WorkspaceSpec.swift#L230).

**Problem.** AF09 removed the root exec of `update-ca-certificates` / `update-ca-trust` and mounts the combined bundle
read-only at two paths. That is the right direction (nothing of the project's image runs as root). It covers less: on
Fedora and RHEL, OpenSSL's default file is `/etc/pki/tls/cert.pem`, a different extracted file, and tools that read the
certificate directory rather than a bundle lose the enterprise roots everywhere. Programs honouring the variables
(`SSL_CERT_FILE`, `CURL_CA_BUNDLE`, `NODE_EXTRA_CA_CERTS`, `REQUESTS_CA_BUNDLE`, `GIT_SSL_CAINFO`) are unaffected.

**Scenario.** A dev container on a RHEL-family image runs a tool built on the system OpenSSL with no variable set;
behind the transparent proxy it now fails certificate validation, where it worked before.

**Confidence.** Moderate: the Fedora layout is from memory and was not checked on an image. Nothing was run.

### GV10 · minor · A push goes to the URL, so remote-name-scoped git settings no longer apply

**Where:** [GitWorkflows.swift:161-176](../../Sources/Engine/Git/GitWorkflows.swift#L161).

**Problem.** AF06 pushes to `plan.remoteURL` instead of the remote's name so the destination cannot be repointed
between the check and the push. The push URL is re-verified first, so pushing by name would be equivalent at that
moment. Settings scoped by remote name are skipped: `remote.<name>.sslVerify`, `.proxy`, `.receivepack` and the like.
`insteadOf` rewriting and URL-scoped credential and TLS settings still apply.

**Scenario.** A self-managed GitLab added with `remote.origin.sslVerify=false` pushes from BelloCode before the change
and fails with a certificate error after it.

**Fix.** None required if the trade-off is intended; worth a line in `docs/features/git-parity.md`.

## 4. Reviewed without finding

  `endpoint.baseURL`, so the comparison holds, and it also catches a stale file whose dead pid was reused.

  `stopping` and `runTask` before it returns; `restartServer` is bounded by the failure limit.

  connection changes; a concurrent pass cannot duplicate one.
- **`MessageModel.update`** (NF02): orders on the server's revision, decoration offset kept apart.
- **Secrets** (`SecretManager.swift`): `mutate` is the only editor of an existing row, its lock is released by `defer`
  on every exit and cannot be entered twice; a grant is re-checked after it is written and withdrawn if the policy
  moved; `pendingEnvironmentSessions` is shown in Settings.
- **Egress re-authorization** (AF15): runs after the last suspension and immediately before `wire.send`, discounts the
  request's own reservations, fails closed when the re-rewrite makes any other use.
- **Workspace user** (`WorkspaceUser.swift`, `WorkspaceExec.swift`, `WorkspaceManager.swift`): parsed from ASCII digits
  with a 32-bit bound; a bare numeric uid gets group 0, so distroless-style images stay usable; the account files are
  read from a container that is created and never started; a racing creator's container is adopted only if it passes the
  same check; the workspace runs with no capabilities and `/tmp/.bellocode` is a `noexec` tmpfs.
- **Docker filter chunk size** (`81265a3`): hex digits only, and the fit check runs before any addition.
- **Dev-container context** (AF07, AF25): every entry is opened relative to an open parent with `O_NOFOLLOW` and must
  be the inode that was listed; FIFOs are opened without blocking and refused.
- **Dockerfile parser** (AF11, AF12) apart from GV01.
- **Push plan** (AF06, AF21): the plan's commit to the plan's URL after re-verifying branch, HEAD and push URL; an
  empty lease value correctly means "must not exist".
- **Stash restore** (AF05): files in the way are checked before anything is applied, the index is restored, and the

- **Rewind isolation** (AF19, AF20): compared by worktree root and repeated right before files are written; an
