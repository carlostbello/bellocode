## New blockers in `a8cfb90`

**R5-01 · Closing a window can discard a pending attachment while BelloCode stays open.** Start with an empty stored draft, paste an image while the draft loads, and switch threads. The handoff keeps the image only in a revision keyed to the old thread model. Close the window before revisiting that thread. Releasing its last lease removes the model, and reopening creates a new owner with an empty draft. The same loss occurs on model eviction. The previous save path cached and archived the image. The new regression reads back through the very same host, which keeps the owner alive throughout. [Handoff](../../Sources/ComposerKit/Host/ThreadModelComposerHost.swift#L212) · [Revision ownership](../../Sources/ComposerKit/Host/ThreadModelComposerHost.swift#L133) · [Window close](../../Sources/BelloCodeApp/Shell/WorkspaceController.swift#L478) · [Eviction](../../Sources/BelloCodeApp/Shell/WorkspaceController.swift#L124) · [Model replacement](../../Sources/Engine/Presentation/Engine.swift#L412) · [Regression readback](../../Tests/ComposerKitTests/RecoveredPromptTests.swift#L375)

**R5-02 · The first read after a handoff can silently discard a newly chosen file mention.** Take a stored draft with an image and the literal text `review @a.swift now`. Before it loads, enter the same words using file completion to select `a.swift`, then leave the thread. Even if the same model survives, the engine collapses the identical plain strings. The new rich-draft join selects the archived draft, copies only attachments from the edit, then saves that result. The user still sees the words, but a later send omits the selected file reference. This case needs neither quit nor eviction. [File completion](../../Sources/ComposerKit/Completion/ServerProviders.swift#L115) · [Text merge](../../Sources/Engine/Presentation/ThreadModel.swift#L612) · [Rich merge](../../Sources/ComposerKit/Host/ThreadModelComposerHost.swift#L250) · [Writeback](../../Sources/ComposerKit/Host/ThreadModelComposerHost.swift#L177)

The same join can also discard an older attachment. A prior text-only handoff followed by quit can leave the archive's text behind the persisted text. On a second handoff, the archived candidate then fails the text comparison, the inferred plain-text candidate matches, and the writeback drops the old attachment. The ordinary archive restore preserves attachments on a text mismatch. [Candidate selection](../../Sources/ComposerKit/Host/ThreadModelComposerHost.swift#L226) · [Ordinary restore](../../Sources/ComposerKit/Host/ComposerDraftArchive.swift#L296)
