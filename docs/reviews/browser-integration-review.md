# Shared Chromium for BelloCode

Design review, 18 November 2026. One supervised browser serves all projects and threads. The profile, site storage and sign-ins belong to the developer. A thread gets a named browse session in that browser. The built-in WebKit preview keeps its existing per-project storage. [Owner decisions](../PLAN.md#0-scope-constraints-from-the-owner-2026-11-16) · [WebKit contract](../features/browser.md)

## Baseline and scope

G7 exercised Debian arm64 Chromium 156, a policy-installed browse CRX, loopback relay, container-side MCP and TigerVNC Xvnc. One opencode agent filled a form, took a screenshot and read a public site. The prototype joined a fixture network directly. Production requires the project-routing proxy and concurrent session binding. [Spike and fixtures](../spikes/G7-chrome-browse-container.md) · [Container integration](../features/containers.md)

## What several agents actually share

On 18 November the latest published release was **v0.1.5**, tagged at `be5528ff2194c8defab74d41e13abb7cb149548e`. G7 read `e1e3b75bc153067020d74e06770750212c9f7e33` but installed the checksum-pinned **release binary and extension zip**. The checkouts differ in relay HTTP handling, CLI help and tests. Their Rust MCP, tab and grouping implementations agree. The plain-tool calls recorded by G7 match this release. **Why earlier research mentions session tools.** The TypeScript tree really implements `session_new/use/adopt/allowlist`. It keys a caller's default off opencode request metadata when available, falls back to a shared default, and supports explicit session IDs. Use changes the current session. Adopt selects an attached page as the session default. The runtime distributed in the Linux platform tarball is Rust. Its tool schema has none of these verbs, and setting the old `OPENCODE_BROWSER_SESSION` cannot supply thread scope. The Rust relay returns 410 for legacy routes. ### Bind the default before a call leaves BelloCode

1. Use **one pooled container-side `browse mcp`** for active threads. One app-owned broker multiplexes request IDs on its stdin and matches out-of-order replies. Opencode's project registrations are location-scoped. A separate registration per thread in the same directory would not give trustworthy caller identity. An MCP per thread would add processes while still sharing the same relay and inventory. [Container routing](../features/containers.md#mcp-servers) · [Upstream pooled proxy][mcp]
2. Expose one approved, location-scoped client-MCP provider through BelloCode. Read opencode's `_meta["ai.opencode/sessionID"]` on **every call**. Verify that thread's location and grant, refuse missing attribution, and forward the approved call to the real binary through a fixed `bellocode-exec --stdio` browser-service target. Use the opencode plain surface, including when the broker initializes the downstream MCP. Preserve image blocks and cancellation end to end. Today's client-MCP result type only carries text, so this seam needs work. [Client-MCP contract](../../Sources/OpenCodeKit/ClientMCP/MCPServerProtocol.swift) · [Stdio relay](../../Sources/ContainerKit/Workspace/StdioRelay.swift)
3. Persist the immutable opencode session ID → group slug (e.g. `bc-<digest>`, collision checked), chosen main ID, selected tab and allowed origins. Forks and children get fresh bindings. Renames keep them. Display the human thread title separately. Supply that group and its options on every new tab, translate ordinary navigation to the selected tab, and bind popups by opener plus relay generation. Unknown or expired targets require reselection.
4. Add **Use Shared Tab…** and **Return to My Tabs**. Store explicit grants for a named thread and tab/group with a lifetime. Sharing a group makes its tabs selectable. Use accepts an attached ID from a verified inventory. Adopt a user tab only after it was lent in Chrome. Apply the binding to list, close, multi-tab calls and future popups. Keep global settings, unrestricted execute and unmanaged bulk operations out of this agent surface. Scoping applies to calls, independent of the sign-ins shared across every tab.
5. Serialize calls on the resolved (browser generation, tab ID), including numeric aliases, group/bulk actions and user-lent tabs. On a deliberately shared tab, grant one thread the driver role until it yields or the person revokes it. On a driver change invalidate prior snapshot refs. Support parallel work on different tabs. Start with **four active calls and 16 queued across threads** as a test budget, fair per thread, bounded bytes as well as count. Give cancel/control a separate priority path, and parked handoffs a bounded wait slot so they cannot exhaust the work slots. Return Busy on overflow.
6. Keep an app-side record of caller, target, grant, pending request and result. `tabs[].busy`, the group and the extension's RUN badge identify a busy tab, not the responsible agent. Show **Driving**, **Waiting for you**, **Last used by** or **Unknown** with the human thread name. Mark the foreground tab only when observed. A single X display shows one foreground page, even when ten background tabs are working. Offer the inventory alongside it. User activation or the handoff in Chrome reveals the group without agents stealing focus.
7. **Take Over** first closes the broker's admission gate, cancels and drains affected calls, and invalidates pending inputs. If the foreground tab cannot be identified reliably, pause all browser calls and say so. Enable one authenticated interactive viewer after acknowledgment. For a requested handoff, allow human input while preserving its waiter, block other agent input and let the genuine Continue finish it. Explicit Resume re-lists tabs and refreshes the snapshot. A dropped viewer never silently returns control. [Handoff][handoff] · [Built-in browser precedent](../features/browser.md#ownership-and-safety)

## One URL and one routing table

Use **`https://<project>.bc:<dev-port>/`** for the workspace and **`https://<service>.<project>.bc/`** for its registered HTTP service (443 maps to the service's declared port). WSS uses the same authority as HTTPS. For example, both browsers open `https://atlas.bc:5173/` and call `https://api.atlas.bc/`. Canonical URLs belong in the toolbar, copied links, agent guidance, redirects and HMR configuration.

1. Allocate a stable, unique DNS label per project from installation state, independent of its display name. If concurrent worktrees expose the same port, allocate a stable worktree-qualified project label, e.g. `atlas-w7.bc`. Publish the exact route in both thread headers. Reserve the suffix locally, keep it out of upstream DNS, and reject unmatched names. `.bc` is a private convention outside IANA's special-use registry. [Special-use names][iana]
2. Attach Chromium to **one internal user-defined bridge** with exactly two members, browser and routing proxy. Use Docker's isolated gateway mode for the enabled address families on a supporting Engine, disable unused IPv6 and publish no ports. An ordinary internal bridge can still reach services on its bridge gateway. Inspect network membership and test denied direct paths on the actual VM. The proxy has separate approved workspace/service and egress connectivity. It terminates connections in user space, with IP forwarding disabled. No project mounts, Engine socket, host networking or direct project joins in the browser. [Docker bridges][bridge] · [Internal networks][internal] · [Gateway modes][gateway]
3. Reserve a proxy IP on that bridge or resolve a single Docker network alias `bc-router`. Set `--proxy-server=https://bc-router:8443` with a matching trusted proxy certificate and **no DIRECT fallback**. Pin browse to its loopback port with `OPENCODE_BROWSER_PORT=19988`. Test the ordered Chromium exception `--proxy-bypass-list="<-loopback>;127.0.0.1:19988"` for the extension's HTTP probe and WS connection. That exception applies to all origins targeting that address: retain relay token, Host/Origin checks, trusted extension ID and pairing. Other loopback, link-local and private destinations are denied at the proxy unless explicitly registered. [Chromium proxy rules][proxy] · [Relay validation][origins]
4. Chromium sends the requested host in its proxy request/CONNECT. Only the proxy resolves project destinations. For every authority and port, look up a generation-checked route to an exact Engine network, container ID and port. This avoids ambiguity between two Compose services both named `web`. On recreation drain old connections, verify health and atomically publish the new route. In the shared workspace reserve distinct listening ports or bind addresses for colliding processes. For per-project mode use that project's network. For docker-only mode register only opted-in container endpoints. A loopback-only dev server needs a scoped in-container forward or an explicit project-interface bind.
5. Route known `.bc` destinations before internet DNS. Reject unknown hosts/ports, userinfo, inconsistent SNI/Host/authority and requests for gateway, metadata, control or unregistered private endpoints. Resolve approved internet/intranet destinations in the existing egress path and validate the final peer on connect/redirect. Apply equivalent restrictions on IPv6, UDP/QUIC, WebRTC and DNS. Test direct TCP/UDP, DNS forwarding and proxy loss using synthetic endpoints. Proxy flags configure Chrome web requests. Network isolation and egress policy enforce the boundary. A separate wildcard DNS service would add a dependency while solving neither TLS nor access control. [Chromium proxy schemes][proxy] · [Docker networking][bridge]
6. Terminate project TLS at the router with a cert valid for the **exact requested host**, signed by an enterprise-approved internal issuer. A `*.bc` leaf does not cover `api.atlas.bc`. Keep signing keys outside the browser. Verify HTTPS upstream where configured, allow HTTP only on the registered private hop. Preserve public Host/port and Origin. Strip client forwarding headers and set trusted forwarded scheme/host. The dev server must know its external origin. Import only approved CA certificates into Chromium NSS and use Mac trust for WK. Show issuer/expiry and a retry on trust failure. [G7 CA test](../spikes/G7/ca-and-downloads.txt) · [Corporate network](../features/containers.md#corporate-network-transparent-proxy-tls-interception)
7. Internet CONNECT normally tunnels TLS through egress and the existing transparent corporate proxy. A tunnel cannot substitute a header inside TLS. For a destination-bound placeholder, the secret manager's approved TLS-terminating path must validate upstream TLS, match the exact destination and grant, substitute there, and strip sensitive response echoes before returning permitted data. Keep policy evaluation per request/redirect, including reused H2 streams. Never derive the caller grant from the current foreground tab, TCP connection or a page-supplied header. A shared Chromium profile provides no trustworthy HTTP-level thread identity. Use broker-issued scoped placeholders with explicit destination/expiry; refuse browser substitution when provenance or non-disclosure cannot be guaranteed. Internet PKI, corporate interception and the internal dev issuer are separate trust decisions. [CONNECT semantics][http] · [Owner's secret contract](../PLAN.md#0-scope-constraints-from-the-owner-2026-11-16)
8. On the Mac, forward **one authenticated proxy endpoint on 127.0.0.1** through the existing Engine exec forward to a dedicated preview listener on the routing proxy. Before loading a project WK view, set its `WKWebsiteDataStore.proxyConfigurations` to a Network.framework `ProxyConfiguration(httpCONNECTProxy:…)` using the loopback listener, per-launch proxy credentials, exact registered match domains and `allowFailover = false`. Preconfigure private preview stores too. The WK request keeps `https://atlas.bc:5173/` all the way to TLS and the origin. Limit the preview listener to approved project routes with no Chromium secret-substitution grants. Unrelated native browsing keeps its existing path. Keep the noVNC viewer on a separate data store. Gate WS, service workers and proxy-down behaviour on supported macOS. [WebKit API][wk] · [Network API][networkapi] · [PortForwarder](../../Sources/ContainerKit/Workspace/PortForwarder.swift)
9. A raw `http://127.0.0.1:<random>/` forward can diagnose a server but changes its origin. Translate a recognized terminal link to its canonical project URL at the UI boundary. PAC/WPAD introduces discovery, bypass and fallback variability. Transparent interception alone needs DNS and an on-path packet router for every dev name. Use explicit proxy selection in both product browsers and retain transparent corporate interception **downstream**. System-wide proxy, DNS edits and public wildcard DNS are unnecessary. [Proxy selection][proxy]

Cache the route table in memory and refresh on Engine events/gaps. Compare cold and warm DNS/TCP/TLS, TTFB, HMR reconnect and proxy CPU against direct synthetic fixtures. Each reused connection avoids one TCP/TLS setup; latency and byte savings depend on workload. [HTTP proxy and H2][proxy] · [HTTP semantics][http]

### Memory, scheduling and disk

- **First reclaim owned idle tabs.** Keep browse's 10-minute idle setting initially. Close thread-owned disposable groups at explicit completion, honoring user-lent tabs, sharing grants, active downloads, capture, handoffs, modified forms and Keep Open. G7's loop left 15 tabs open. Its 789 MiB versus 374 MiB warm-idle samples leave ~415 MiB of difference. An initial target of **100–300 MiB** reclaimed in that workload is plausible; memory shared between processes and allocator/cache retention make a per-tab guarantee unsound. [Browse cleanup][lookup] · [Raw samples](../spikes/G7/resources.jsonl)
- **Allow Chromium to discard eligible background pages.** Compare default with `HighEfficiencyModeEnabled=true` and balanced `MemorySaverModeSavings=1`. A discarded tab retains its strip entry but reloads its document. Exempt important sites and protect lent tabs with unsaved work. Revalidate tab/document/ref identity after reload. A debugger attachment may inhibit discard: measure actual discards. G7 did not verify these policies on Debian. Avoid disabling background throttling or memory-pressure handling. Use controlled cgroup pressure, faults, swap and OOM events to tune admissions before changing Chromium heuristics. [Memory Saver][memory] · [Discard and reload][discard]
- **Keep site isolation.** Desktop Chromium's renderer limit is soft. Different sites and out-of-process frames may exceed it for security. A/B `--renderer-process-limit=8` against default on 15- and 30-tab workloads. Expect little gain on unrelated sites, potentially fewer processes on same-site pages, more contention and a larger crash impact there. Keep the default unless p95 input and parallel throughput hold. Avoid single-process mode, forced process-per-site and disabling site-per-process on a profile containing enterprise logins. [Process model][models] · [Switch definition][switches]
- **Check the actual memory constraint.** Start with the G7 2 GiB cgroup limit, 2 vCPU, 1,024 PIDs and 1 GiB `/dev/shm` ceiling. A tmpfs ceiling is not reserved RAM. G7 also passed `--disable-dev-shm-usage`, routing shared files to temporary storage. Retest without it, track tmpfs, cgroup memory and renderer crashes together. Linux VM-wide available memory may differ from the cgroup headroom. Avoid test-only pressure overrides. Apply backpressure before a single large screenshot or tab burst kills every thread. [G7 launcher](../../Spikes/ChromeBrowse/run.sh) · [Entrypoint](../../Spikes/ChromeBrowse/entrypoint.sh) · [Chromium switch][shm]
- **Bound the right bytes.** Start with `DiskCacheSize=134217728` (128 MiB hint), split cache and export/download staging from the durable profile. Keep IndexedDB, Local Storage, service workers, Cookies, Local State, extension and relay pairing state together. Test service-worker Cache Storage separately. A disk-cache hint covers neither all caches nor origin storage. More misses mean more traffic. [Cache policy][cache]
- Propose 1 GiB staging and an 80% warning on a 4 GiB profile budget with operator-adjustable limits. Docker named volumes do not universally enforce byte quotas. Measure usage and free space, reserve shutdown headroom, stop admitting new captures/downloads and apply real filesystem quotas only on validated storage drivers. Offer scoped cleanup and export. Never evict credentials, live SQLite/WAL files or origin data behind a running browser. Show actual reclaimable bytes and request explicit confirmation for profile deletion.
