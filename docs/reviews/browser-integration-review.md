# Shared Chromium for BelloCode

Design review, 18 November 2026. One supervised browser serves all projects and threads. The profile, site storage and sign-ins belong to the developer. A thread gets a named browse session in that browser. The built-in WebKit preview keeps its existing per-project storage. [Owner decisions](../PLAN.md#0-scope-constraints-from-the-owner-2026-11-16) · [WebKit contract](../features/browser.md)

## Baseline and scope

G7 exercised Debian arm64 Chromium 156, a policy-installed browse CRX, loopback relay, container-side MCP and TigerVNC Xvnc. One opencode agent filled a form, took a screenshot and read a public site. The prototype joined a fixture network directly. Production requires the project-routing proxy and concurrent session binding. [Spike and fixtures](../spikes/G7-chrome-browse-container.md) · [Container integration](../features/containers.md)

## What several agents actually share

On 18 November the latest published release was **v0.1.5**, tagged at `be5528ff2194c8defab74d41e13abb7cb149548e`. G7 read `e1e3b75bc153067020d74e06770750212c9f7e33` but installed the checksum-pinned **release binary and extension zip**. The checkouts differ in relay HTTP handling, CLI help and tests. Their Rust MCP, tab and grouping implementations agree. The plain-tool calls recorded by G7 match this release. [Release][release] · [Source comparison][comparison] · [G7 build](../../Spikes/ChromeBrowse/Dockerfile) · [Recorded calls](../spikes/G7/e2e-tool-calls.json)

| Question | Behaviour of the shipped Rust implementation |
|---|---|
| What is a session? | The durable product concept is the BelloCode thread. In browse the work handles are **tabs**. A tab has a relay numeric ID, optional caller-chosen ID and optional group label. Configure extension grouping per task to show the labels in Chrome. A group can span several tabs. It has no current page, owner credential or independent sign-in. [User guide][usage] · [Extension grouping][groups] |
| Create or use? | Bare `navigate(url)` opens a new background tab. `tabs(action:"new", id:"bc-a-main", group:"bc-a", url:…)` creates a named tab. Reopening that ID returns the existing tab without navigating it. Pass its ID as `tab` for subsequent calls. A group filters `tabs list` and selects members for close. A group label alone does not resolve to a page. IDs are lowercase slugs starting with a letter, ≤64 characters. Group labels are trimmed to 63 characters. [Tools][tools] · [Lookup][lookup] · [Registry][registry] |
| Adopt or share? | A real toolbar click lends a user tab. Pass its returned tab ID. Closing a lent tab releases it to the user. Two agents can also use the same agent tab by ID. The unfiltered inventory lists every agent and lent tab, including URLs and titles. Agreement about which ones to use is a caller convention. [User guide][usage] · [Tools][tools] |
| Allowlists? | Set `allowedOrigins` and `readOnly` **on creation of each tab**. Popups inherit the opener's options. An out-of-policy navigation can be refused, a committed document blanked, or a fresh popup closed. Up to 100 patterns, exact hosts for private-address destinations. Widen by creating a new approved tab. Top-level navigation rules do not filter every subresource. The proxy must enforce network policy. [Domain rules][domain] · [Navigation][tabsrc] · [CDP guardrails][guardrails] |
| Client identity? | MCP reads `clientInfo.name` on initialize or the modern per-request clientInfo metadata. `OpenCode-Browser-Client: opencode` selects plain tools. Other clients ordinarily get execute/status/tabs. All use the installation bearer token. The PID identifies process lifetime. A random per-call key supports cancellation. None identifies a BelloCode thread or gives it a private inventory. [MCP][mcp] · [HTTP client][relayclient] · [Surface][surface] |
| One relay, how many calls? | One authenticated loopback relay dispatches concurrent HTTP calls to one paired extension WebSocket, multiplexing command IDs and replies. Each stdio MCP spawns a worker per tool call and serializes writes to stdout by JSON-RPC ID. Multiple MCP processes can connect too. No general numeric agent limit or global admission semaphore appears on this path. VM resources, outstanding calls and per-operation limits constrain it. [Dispatch][dispatch] · [Extension link][linksrc] · [MCP][mcp] |
| What if they touch one tab? | A call with a **top-level chosen string** `tab` reserves the target and receives a busy error if another call already holds it. Concurrent creation reserves the chosen ID too. The numeric-ID path and entries in a `tabs` array skip that reservation. Background recording/network capture counts as busy for cleanup but does not exclude calls. Even two successful named-ID calls can alternate between a snapshot and the click that uses it. [Dispatch][dispatch] · [Regression cases][browsetests] |
| Who wins a handoff? | One pending handoff per tab. A second handoff reaching that handler cancels its predecessor. Default wait 600 s. A genuine Continue or toolbar click completes it. Close, timeout, cancellation or client death can end it. Other tabs can keep working. The toolbar on a busy tab can stop calls and reclaim it outside a handoff. The browser debugging infobar's Cancel disconnects all tabs. [Handoff][handoff] · [Toolbar][tabsrc] · [User guide][usage] |

**Why earlier research mentions session tools.** The TypeScript tree really implements `session_new/use/adopt/allowlist`. It keys a caller's default off opencode request metadata when available, falls back to a shared default, and supports explicit session IDs. Use changes the current session. Adopt selects an attached page as the session default. The runtime distributed in the Linux platform tarball is Rust. Its tool schema has none of these verbs, and setting the old `OPENCODE_BROWSER_SESSION` cannot supply thread scope. The Rust relay returns 410 for legacy routes. [Old caller map][oldcaller] · [Old session tools][oldsession] · [Release packaging][pack] · [Earlier research](../research/05-opencode-integration.md#6-the-opencode-browse-plugin)

### Bind the default before a call leaves BelloCode

1. Use **one pooled container-side `browse mcp`** for active threads. One app-owned broker multiplexes request IDs on its stdin and matches out-of-order replies. Opencode's project registrations are location-scoped. A separate registration per thread in the same directory would not give trustworthy caller identity. An MCP per thread would add processes while still sharing the same relay and inventory. [Container routing](../features/containers.md#mcp-servers) · [Upstream pooled proxy][mcp]
2. Expose one approved, location-scoped client-MCP provider through BelloCode. Read opencode's `_meta["ai.opencode/sessionID"]` on **every call**. Verify that thread's location and grant, refuse missing attribution, and forward the approved call to the real binary through a fixed `bellocode-exec --stdio` browser-service target. Use the opencode plain surface, including when the broker initializes the downstream MCP. Preserve image blocks and cancellation end to end. Today's client-MCP result type only carries text, so this seam needs work. [Client-MCP contract](../../Sources/OpenCodeKit/ClientMCP/MCPServerProtocol.swift) · [Stdio relay](../../Sources/ContainerKit/Workspace/StdioRelay.swift)
3. Persist the immutable opencode session ID → group slug (e.g. `bc-<digest>`, collision checked), chosen main ID, selected tab and allowed origins. Forks and children get fresh bindings. Renames keep them. Display the human thread title separately. Supply that group and its options on every new tab, translate ordinary navigation to the selected tab, and bind popups by opener plus relay generation. Unknown or expired targets require reselection.
4. Add **Use Shared Tab…** and **Return to My Tabs**. Store explicit grants for a named thread and tab/group with a lifetime. Sharing a group makes its tabs selectable. Use accepts an attached ID from a verified inventory. Adopt a user tab only after it was lent in Chrome. Apply the binding to list, close, multi-tab calls and future popups. Keep global settings, unrestricted execute and unmanaged bulk operations out of this agent surface. Scoping applies to calls, independent of the sign-ins shared across every tab.
5. Serialize calls on the resolved (browser generation, tab ID), including numeric aliases, group/bulk actions and user-lent tabs. On a deliberately shared tab, grant one thread the driver role until it yields or the person revokes it. On a driver change invalidate prior snapshot refs. Support parallel work on different tabs. Start with **four active calls and 16 queued across threads** as a test budget, fair per thread, bounded bytes as well as count. Give cancel/control a separate priority path, and parked handoffs a bounded wait slot so they cannot exhaust the work slots. Return Busy on overflow.
6. Keep an app-side record of caller, target, grant, pending request and result. `tabs[].busy`, the group and the extension's RUN badge identify a busy tab, not the responsible agent. Show **Driving**, **Waiting for you**, **Last used by** or **Unknown** with the human thread name. Mark the foreground tab only when observed. A single X display shows one foreground page, even when ten background tabs are working. Offer the inventory alongside it. User activation or the handoff in Chrome reveals the group without agents stealing focus.
7. **Take Over** first closes the broker's admission gate, cancels and drains affected calls, and invalidates pending inputs. If the foreground tab cannot be identified reliably, pause all browser calls and say so. Enable one authenticated interactive viewer after acknowledgment. For a requested handoff, allow human input while preserving its waiter, block other agent input and let the genuine Continue finish it. Explicit Resume re-lists tabs and refreshes the snapshot. A dropped viewer never silently returns control. [Handoff][handoff] · [Built-in browser precedent](../features/browser.md#ownership-and-safety)
