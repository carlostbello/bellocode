## New blocker

**R4-01 · An in-flight send can erase another window's newly saved draft.** The composer clears the submitted revision, then asynchronously prepares attachments. During that wait, a second window can save a new draft with the same visible text and different mention tokens. On dispatch, `ThreadModel.send` clears the new draft solely because the strings match. R4b now makes the second editor follow that clear, removing its editable copy as well. The outgoing message contains the original submission's mentions. A successful send leaves the later draft's text empty, and restoring its rich record with empty text drops its mentions. The clear needs to belong to the submitted revision through dispatch. [Composer clear](../../Sources/ComposerKit/Host/ComposerController.swift#L404) · [Attachment preparation](../../Sources/ComposerKit/Host/ThreadModelComposerHost.swift#L284) · [Dispatch](../../Sources/ComposerKit/Host/ThreadModelComposerHost.swift#L209) · [Second clear](../../Sources/Engine/Presentation/ThreadModel.swift#L230) · [Other editor follows](../../Sources/ComposerKit/Host/ComposerController.swift#L249) · [Archive restore](../../Sources/ComposerKit/Host/ComposerDraftArchive.swift#L296)

## Public documentation

- The README and guide promise that every command runs in a container. The optional **Host shell, docker only** mode runs the sandboxed Docker client on the Mac and disables terminals. Both documents also say the user's opencode data is never touched. Explicit **Import from opencode** reads accounts from the selected installation. Qualify both promises where users first encounter them. [README introduction](../../README.md#L8) · [README first run](../../README.md#L95) · [Guide setup](../USER-GUIDE.md#L28) · [Guide isolation claim](../USER-GUIDE.md#L57) · [Execution modes](../USER-GUIDE.md#L180) · [Importer](../../Sources/Engine/Auth/CredentialImporter.swift#L114)
- The guide says every project's `AGENTS.md` is used. Users resuming older sessions through a linked folder, or resuming a session whose pinned checkout was replaced, can get no repository instructions. The release notes also promise that an unreadable watermark withholds instructions. The implementation treats the session as old and still permits a link-free path. After eviction, such a path can be pinned to a different real directory at the same address. [Guide](../USER-GUIDE.md#L136) · [Release notes](../RELEASE-NOTES.md#L184) · [Watermark failure](../../Plugin/src/pins.ts#L192) · [Unpinned lookup](../../Plugin/server.ts#L230) · [Documented eviction limit](../features/opencode-config.md#L135)
- The release notes promise that rewind prepends the prompt and waits for a slow draft. The visible composer inserts at its current selection, replacing selected text, and can bypass the wait described in AV2-02. The index dispositions that call AF08, AV2-02 and GR3-01 fixed should reflect the open cases above. [Release notes](../RELEASE-NOTES.md#L197) · [Visible insertion](../../Sources/ComposerKit/View/ComposerViewController.swift#L439) · [Review index](README.md#L24)
- The guide gives the minimum for Brokered and Placeholder secrets as eight characters. The setting checks **eight UTF-8 bytes**, which matters for non-ASCII values. [Guide](../USER-GUIDE.md#L215) · [Validation](../../Sources/Engine/Secrets/SecretManager.swift#L750)

**Known limitations:** Auto's shell analysis is best effort, linked checkout paths can suppress repository instructions, quitting can discard a pending rewind, and drafts for threads still being created have no shared revision.
