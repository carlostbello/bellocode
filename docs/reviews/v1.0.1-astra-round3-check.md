## New blocker

**R3-01 — Rewind can overwrite a saved draft from an idle second window.** With the same thread open twice, the active window can have a newer saved draft while the idle window still displays an older copy. Edit from Here flushes the active editor, then directs the other editor to prepend the recovered prompt to its own local copy and save it to the same thread. That second write discards the active window’s additional text or attachments from storage. Closing without further edits leaves the stale copy for relaunch. This overwrite was introduced by `65e25c8`. [Rewind write order](../../Sources/BelloCodeApp/Shell/MainWindowController+Git.swift#L424) · [Second editor’s write](../../Sources/ComposerKit/Host/ComposerController.swift#L352) · [Shared draft storage](../../Sources/ComposerKit/Host/ThreadModelComposerHost.swift#L134) · [Close flush guard](../../Sources/ComposerKit/Host/ComposerController.swift#L224)

The two-editor regression uses separate fake hosts with identical initial drafts. The app-level regression opens different threads in its two windows. Neither exercises divergent editors saving to one underlying draft. Recovery needs one authoritative rich-draft write, with any divergent edits preserved when the other views reconcile. [Composer regression](../../Tests/ComposerKitTests/RecoveredPromptTests.swift#L23) · [Window regression](../../Tests/BelloCodeAppTests/WindowLifecycleTests.swift#L69)

**Known limitations and release trade-offs.** Omitting instructions for in-checkout links and requiring Git ≥ 2.46 or Apple Git-155 for approved pushes are acceptable fail-closed choices. Memory-only root pins are unacceptable while resuming a session can silently adopt another checkout’s instructions (AF08).
