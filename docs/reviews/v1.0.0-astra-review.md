# BelloCode v1.0.0 — independent code review

**Release reviewed:** `v1.0.0`, `71238ec9dc8ee0bcb4bb26385f703d9e4a5aa55c`, opencode 2.3.2, arm64. **Disposition: prioritize a corrective release.** A repository can supply a host file as model context without a file-tool approval; a managed secret can change before the policy protecting it does; and a successful handoff can discard the only named copy of staged content. These are not conclusions drawn from failing unit tests: the debug build and all 94 selected tests passed.

I compared the tag to the release review at `884d86c`, including merges `1ef43d6` (config/CLI/trust), `a3bedf8`, `b162849`, `72eb51e` (release repairs), `89b562c` (live-suite repairs) and `71238ec` (models). I used the earlier reviews as a regression index, `docs/PLAN.md` §0 as the product contract, and the feature notes and implementation as separate evidence. Shared browser sign-ins, code roots, the host Docker CLI, nonblocking Full-access notices, and the **explicit global** opt-in to native repository plugins are owner decisions, not findings. Trusting text in one repository is *not* that global opt-in.

**Evidence key:** findings are source traces unless marked **observed**. Observed fixtures used no real projects or secrets. Critical denotes possible loss of protected data, arbitrary out-of-scope host file access, or loss of user work without a normal recovery path. Major denotes a narrower policy failure, wrong durable result, or a broken operational guarantee. File references are relative to the reviewed tag.

## Findings, in priority order

### A01 · Critical — Repository instructions can disclose a host file on the first prompt

`Plugin/src/project.ts:120`, `Plugin/src/project.ts:39`, `Plugin/server.ts:179`. The default, untrusted path accepts anything named `AGENTS.md` that exists and is not a directory. The synchronous read follows links; the prompt hook then inserts its result as a session instruction. Opening a checkout whose instruction entry resolves to private text outside the project can send that text to the provider without a read-tool event, approval, or even a trusted-project grant. The size check is **after** the read; a large or non-regular entry can also block the server before the two-second instruction-write timeout starts. **Fix:** read bounded bytes from a verified regular file reached beneath an open project root, rejecting link traversal in every component. Use the same reader for project agents, commands and skills. Test an external link, a non-regular file and oversized text with harmless fixtures; assert that no rejected content reaches the prompt.

### A02 · Critical — A new Keychain value can be used under the previous policy

`Sources/Engine/Secrets/SecretManager.swift:299`, `Sources/Engine/Extras/SecretService.swift:173`, `Sources/Engine/Extras/ExtrasHub.swift:790`. Replacing a commands-only label with a brokered value overwrites the existing Keychain account **before** awaiting the label write and persisting the new policy/revision. During that suspension, or after a metadata-write failure, a pending command can pass the old revision check and receive the new value. For a fresh account, a crash after label persistence but before policy persistence leaves a label that `SecretManager.swift:212` adopts as a legacy commands-only secret. Quarantining malformed rows does not cover an absent row. **Fix:** durably mark a pending, unusable generation first, write to a new Keychain account, then atomically activate its policy and account pointer. On restart, quarantine incomplete updates instead of adopting them. Fault-inject at each store boundary, including while an old approval is answering. Residual R03/R09.

### A03 · Critical — CLI discovery exports the server-wide password into the agent's host-file domain

`Sources/OpenCodeKit/Server/ServerSupervisor.swift:366`, `Sources/OpenCodeKit/Server/OpenCodeIsolation.swift:118`, `Sources/Engine/Sync/Mapping.swift:368`. Publication is atomic, the file is `0600`, and the normal wrapper passes the password by environment, not argv. Those protect against *other users* and accidental command-line disclosure, not an opencode host file tool running as this user. In Full access, a read of the app's support directory can return the **reusable server password**, not merely the current thread's authority. The protected-path classification in `Sources/Engine/Auto/RiskPolicy.swift:49` is not a deny in that mode. A loopback listener limits network reachability; it doesn't undo disclosure to a model or another local caller. **Fix:** do not give an ordinary readable file the authority of the supervised server. Broker scoped CLI operations through an app-owned IPC boundary with client authentication, and keep management secrets outside the agent's host read domain. Test with a synthetic marker using the actual host-file boundary, including Full access. No connection file was opened in this review.

### A04 · Critical — A successful worktree handoff loses staged-only content

`Sources/Engine/Git/GitWorkflows.swift:207`, `Sources/Engine/Git/GitWorkflows.swift:249`, `Sources/Engine/Git/WorktreeLifecycle.swift:109`. Restore applies the stash **without restoring the index**; no unmerged entries is treated as verification. Success drops the stash and deletes the private recovery ref. **Observed:** in a disposable repository, HEAD, the index and the working copy held three different contents for one path. The same stash/apply sequence returned success in the new worktree: index = HEAD, working file = final edit. The intermediate staged version existed in the saved stash's index parent, not in the destination. Dropping both names leaves no normal recovery handle. The rollback path uses the same restore helper. **Fix:** restore and verify the index tree independently of the working tree and untracked files, in both directions. Keep the named recovery ref on any mismatch. Add the three-content fixture to the handoff suite. Residual R04.

### A05 · Critical — Rewind's file writes are not confined to the worktree through ancestor links

`Sources/Engine/Git/WorkingCopy.swift:104`, `Sources/Engine/Git/WorkingCopy.swift:112`, `Sources/Engine/Git/WorkingCopy.swift:193`. The snapshot distinguishes a symlink at the **leaf**; the temp-file write and rename resolve the entire parent pathname again. If a directory above a missing file is replaced by a link after planning, the leaf can still compare as missing, and rewind creates a file in an unrelated host directory. This work is done by the app's filesystem code, not by the sandboxed Git subprocess. **Fix:** anchor snapshot, create, rename, rollback and cleanup to validated directory descriptors beneath the worktree; reject ancestor links or identity changes. Use the existing `beforeReplace` seam with two disposable directories and assert the outside one remains untouched.

### A06 · Major — The filtered Docker endpoint does not confine Docker's client-side host reads

`Sources/ContainerKit/Workspace/HostDockerCommand.swift:125`, `Sources/ContainerKit/Workspace/HostDockerCommand.swift:171`, `Sources/bellocode-exec/main.swift:136`. Leading endpoint overrides are now checked, but local Compose inputs and build contexts are forwarded as host operands. The Docker CLI can read/render a file, or collect a context, **before** any daemon request is available to the socket filter. A Host-Docker session aimed at one project can therefore consume private user-readable input outside its roots; denying the ensuing container create is too late. **Fix:** run even this client in a filesystem-restricted process with only approved roots and necessary runtime files, or expose a typed, narrowly scoped interface that confines every local input. Include a client-only operation in the negative tests; a mock daemon recording no requests is not proof that nothing was read. Distinct from R01's repaired flag ordering.

### A07 · Major — The gateway trusts a claimed input hash, then launches a mutable tag

`Sources/ContainerKit/Network/EgressGatewayImage.swift:50`, `Sources/ContainerKit/Network/EgressGateway.swift:162`, `Sources/ContainerKit/DockerFilter/DockerFilterPolicy.swift:706`. The dedicated `node:22-bookworm-slim` base is digest-pinned. But an existing tagged image is accepted solely on a public label describing the **inputs**. That label is not evidence of which image bytes BelloCode built. The build policy checks collisions with an *existing* tag and rewrites request labels; it does not reserve the gateway repository or authenticate image metadata. A conflicting image already in the shared daemon at first use, or a tag changed between check and create, can run as the gateway with its runtime capability. **Fix:** reserve the internal image namespace across agent-facing image operations, capture/retain the actual trusted build's immutable image ID in app-owned state, and create by that ID. On unknown provenance rebuild or refuse. This does not require enterprise image signing. Residual R08; daemon behavior was not exercised.

### A08 · Major — Registry approval covers the first Dockerfile, not necessarily the effective one

`Sources/ContainerKit/DockerFilter/BuildContextScanner.swift:103`, `Sources/ContainerKit/DockerFilter/DockerFilterProxy.swift:416`. Both the plain and gzip paths stop inspection after the first matching regular file; subsequent archive entries are forwarded unchecked. A tar can contain more than one entry for the same resulting pathname. If the builder's unpacker replaces an earlier entry with a later one, the build uses a Dockerfile whose bases were never evaluated. Regardless of the daemon version's duplicate handling, the filter cannot establish equality with the file actually consumed. **Fix:** stage or canonicalize a bounded context, reject ambiguous names/duplicates and link or metadata aliases, and submit only the validated representation. Test duplicates late in both compressed and uncompressed streams and require refusal independently of daemon interpretation. Residual R14.

### A09 · Major — Auto caches permission decisions by a lossy display summary

`Sources/Engine/Auto/AutoReviewer.swift:75`, `Sources/Engine/Auto/AutoReviewer.swift:80`, `Sources/Engine/Auto/AutoReviewer.swift:148`. The reviewer sees at most eight targets, clipped/redacted arguments and a bounded purpose. The *same projection* is hashed for the short-lived allow cache; the model key also omits variant. Two different operations which both reach review can therefore reuse one approval merely because the distinction is outside the displayed portion. This is not a hash collision and the unknown-session R11 fix doesn't prevent it. **Fix:** separate presentation from authorization identity. Bind reuse to the full canonical operation, project/session context, policy and exact reviewer selection without logging raw inputs. Escalate rather than auto-allow when security-relevant input cannot be represented to the reviewer. Test two distinct requests with identical presentations.

### A10 · Major — Revoking repository trust can report success while the old config remains active

`Sources/Engine/OpenCodeConfig/OpenCodeConfigService.swift:140`, `Sources/Engine/OpenCodeConfig/OpenCodeConfigService.swift:154`, `Plugin/server.ts:1029`. After the SQLite change, failure to write the plugin trust file is discarded. The service ignores the reload response and clears `trustPending` on transport success. The plugin itself uses `allSettled` without checking rejected transform reloads. Thus a failed mirror write can leave the plugin accepting the old trust list; alternatively, an old command/agent can stay registered even though the newly computed listing says otherwise. **Fix:** persist desired and applied generations, propagate mirror/transform failures, and require acknowledgement of the actual revision and registrations. Block stale trusted operations while revocation is pending. Test disk failure and one rejected transform separately. Migration v14 establishes the table, not this acknowledgement.

### A11 · Major — Trust crosses into independent nested repositories

`Plugin/src/project.ts:86`, `Plugin/src/project.ts:249`, `Sources/Engine/OpenCodeConfig/OpenCodeConfigService.swift:122`. Settings tests the exact directory in SQLite. The plugin instead authorizes descendants by pathname prefix **before** finding their nearest Git root. A separately opened repository inside a trusted checkout can thus supply its own agents, commands and skills while its Settings toggle says untrusted. Normal subdirectories of *one* repository should inherit trust; a different repository is the boundary. **Fix:** resolve the same canonical repository/worktree identity on both sides, then apply an explicit inheritance policy. Test trusted outer/untrusted nested repositories and revocation with both locations active.

### A12 · Major — Broker redirects reuse a pre-revocation secret snapshot

`Sources/SecretKit/SecretBroker.swift:97`, `Sources/SecretKit/SecretBroker.swift:128`, `Sources/SecretKit/SecretBroker.swift:152`. Each redirect is checked against bindings, but those bindings, scope and value were copied before the first dispatch. For an unlimited binding there is no persistence callback to reconsult the manager. If the owner revokes the secret or narrows its scope while the first allowed hop is waiting, a **new** request after the redirect can still use it. This is not a request to recall bytes already sent. **Fix:** on each outbound dispatch resolve the account/revision against current grant, scope, mode and bindings; abort on change. Test with a gated fake first response, revoke before releasing it, and assert no second send. Residual R13 for this path.

### A13 · Major — A missing CLI discovery record is not an exclusive database lease

`Sources/OpenCodeKit/Server/ServerSupervisor.swift:265`, `Sources/OpenCodeKit/Server/ServerSupervisor.swift:328`, `Sources/OpenCodeKit/Server/OpenCodeCLI.swift:159`, `Sources/OpenCodeKit/Server/OpenCodeIsolation.swift:134`. The app publishes after readiness and withdraws before shutdown completes. A management command during either interval can infer “offline” and start a private server on the same data. Two offline commands can also make that decision at the same time; an app can launch during a long shell login. Additionally, *any* failed `lstat` is reported as missing. SQLite serialization alone doesn't serialize two independent opencode runtimes and their state. **Fix:** acquire a shared-protocol **exclusive lifetime lease** per data root before starting either kind of server; distinguish starting, stopping, inaccessible and absent. Validate loopback and server identity, not only PID liveness, before attaching. Test transitions with barriers, not sleeps.

### A14 · Major — A current-only submodule can survive a “complete” rewind

`Sources/Engine/Git/GitCheckpoints.swift:98`, `Sources/Engine/Git/WorkingCopy.swift:119`, `Sources/Engine/Presentation/Engine+GitParity.swift:96`. The raw parser supplies both modes, but planning switches only on the checkpoint's mode. When a gitlink exists only on the **current** side, the checkpoint mode is missing and the current directory snapshots as no file. The resulting delete is a no-op; the conversation can still be committed to the earlier point while the submodule remains. The path-count limit and ordinary executable/leaf-link fixes do hold. **Fix:** reject unsupported modes on either side before any writes, and represent missing, unreadable and unsupported entries separately. Cover gitlink additions as well as deletions, asserting the conversation commit is never issued. Residual R26.

### A15 · Major — Pasting a new attachment can evict an unsent draft's or outbox's file

`Sources/ComposerKit/Host/AttachmentFileStore.swift:70`, `Sources/BelloCodeApp/Launch/AppDelegate.swift:63`, `Sources/ComposerKit/Host/ComposerDraftArchive.swift:135`. Launch cleanup honors draft and outbox references. Ordinary materialization runs the same eviction policy with **only the folder just written** protected. An older still-referenced paste, outside the grace period, can be removed due to age or budget; restore silently filters the missing file. The owner can send a seemingly intact draft without its intended attachment, or a queued send can lose its backing file. **Fix:** share the live reference/pin set across all eviction paths, including during writes. Reject a new paste visibly if pinned items exhaust the budget. Test a pinned old draft and an outbox item at the write-time limit. Residual R28.

### A16 · Major — An older draft writer can resurrect a cleared attachment

`Sources/ComposerKit/Host/ComposerDraftArchive.swift:70`, `Sources/ComposerKit/Host/ComposerDraftArchive.swift:84`, `Sources/ComposerKit/Host/ComposerDraftArchive.swift:98`, `Sources/ComposerKit/Host/ComposerDraftArchive.swift:114`. The writer removes its `latest` entry before suspending to materialize bytes. A later save/clear can finish while it is suspended. Cancelling the older task does not prevent its eventual atomic write; `flush` sees no such `latest` entry and does not join an in-flight writer. An older attachment can reappear after Send, or quit can finish before the only durable copy exists. **Fix:** serialize commits per key, fence the final rename/delete by generation, and drain in-flight work on flush. Gate materialization in a test, then clear, flush, and reopen. Residual R28, independent of eviction.

### A17 · Major — Concurrent model edits can silently overwrite each other

`Sources/Engine/Models/ModelSettingsService.swift:192`, `Sources/Engine/Models/ModelSettingsService.swift:196`. Re-reading the original and then doing an atomic replace is not compare-and-swap. Two edits to *different* keys can both pass the equality check and write whole-file replacements; whichever runs last drops the other's edit. The service's generation controls the loading indicator, not what gets published as applied. A second Settings window or a simultaneous CLI/editor change suffices. **Fix:** serialize BelloCode edits per file, combine queued key patches, and coordinate/conflict-check the replacement against external writers; on conflict preserve the competing versions rather than claim both saves. Re-read committed state before reporting it. Test interleaved default/title writes and an external save.

### A18 · Major — The dev-container tag describes a different snapshot from the one built

`Sources/Engine/Containers/DevContainers.swift:167`, `Sources/Engine/Containers/DevContainers.swift:185`, `Sources/ContainerKit/Workspace/DevContainer.swift:58`. The Dockerfile bytes are captured, but the rest of the context is hashed and later given to buildx as a *live directory pathname*. An ordinary save between these operations can put new bytes in an image tagged for the old tree; reverting the save then appears to hit a valid old image. Reopening by path also loses the earlier directory-identity check. **Fix:** hash and upload the same bounded immutable context, including the Dockerfile and ignore rules; do not reopen the source tree to perform the build. Test by gating the builder and changing a context file after fingerprinting. Residual R15/R16.

### A19 · Major — A failed Chrome stop is shown as a successful stop

`Sources/Engine/SharedBrowser/BrowserSupervisor.swift:345`, `Sources/Engine/SharedBrowser/BrowserSupervisor.swift:352`. If the runtime stop request fails, the supervisor just records `stop-error`, invalidates tab handles, reports `.stopped` and has already cancelled monitoring. On a transient daemon disconnection, the shared signed-in Chrome can still be running while the owner is told its tabs were closed. The ordinary Stop guard no longer admits a retry in that state. **Fix:** distinguish stopped from stop-unconfirmed, reconcile the owned container by identity, and retain retry/monitoring until termination is verified. Test runtime failure while inspection still reports running. Different from R23's repaired drain timer.

### A20 · Major — A Git deadline can expire without completing the task

`Sources/Engine/Git/GitRunner.swift:272`, `Sources/Engine/Git/GitRunner.swift:370`, `Sources/Engine/Git/GitRunner.swift:374`. Deadline and cancellation signal TERM, but completion still needs process exit **and both pipe EOFs**. An unresponsive child or a helper retaining a pipe can therefore strand a Git operation, teardown and its continuation indefinitely. Using a continuous-clock timer is necessary but does not enforce completion. **Fix:** add owned-child escalation/reaping and a bounded final drain with handler removal/descriptor close. Exercise both TERM refusal and a surviving pipe writer in disposable process fixtures. Do not signal unrelated processes.

### A21 · Major — Reusing a running gateway can skip the step that made it usable

`Sources/ContainerKit/Network/EgressGateway.swift:148`, `Sources/ContainerKit/Network/EgressGateway.swift:155`. Creation starts the relay, waits for readiness and only then connects its outside network. If readiness or network attachment fails after start, the container remains running. Retry sees the matching config label and returns success without checking either condition; downstream operations can fail indefinitely despite a green setup result. **Fix:** reconcile readiness and exact network membership on reuse, repair missing attachments safely, or discard the failed owned instance. Test failure on the last setup operation followed by retry.

### A22 · Major — Malformed build metadata can trap the filter instead of returning a refusal

`Sources/ContainerKit/DockerFilter/BuildContextScanner.swift:181`, `Sources/ContainerKit/DockerFilter/BuildContextScanner.swift:98`. The tar size parser accepts a signed `Int`; there is no nonnegative check before the capture/skip state uses a count in collection operations. Malformed archive metadata can therefore cause a negative-length collection operation in the process hosting the filter instead of a scoped Docker error. Gzip decoding does not validate this tar invariant. **Fix:** accept only the permitted unsigned size encoding, use checked padding arithmetic, validate state sizes before slicing, and reject malformed input for that connection. Add property tests asserting the scanner always returns an outcome or asks for more bytes, never traps. Source-only; no crash input was run.

### A23 · Major — The Models pane's deferred reload can cancel approvals without confirmation

`Sources/BelloCodeApp/Settings/ModelsSettings.swift:110`, `Sources/BelloCodeApp/Settings/ModelsSettings.swift:176`, `Sources/BelloCodeApp/Settings/ModelsSettings.swift:219`. Saving a model checks outstanding approvals/questions before reloading. But after choosing **Save Only**, the follow-up **Reload opencode Now** button calls `reloadServer` directly. Approvals still pending, or new since the save, can be cancelled without the advertised warning. **Fix:** route every user-initiated global reload through a single confirmation that reads current counts immediately before dispatch; keep the saved preference and pending status on cancel. Test an approval arriving between Save Only and Reload Now.

### A24 · Minor — An inherited development override receives the production CLI password

`Sources/bellocode-opencode/main.swift:28`, `Sources/bellocode-opencode/main.swift:59`, `Sources/OpenCodeKit/Server/OpenCodeCLI.swift:154`. Even in a packaged build, the wrapper accepts an executable selected by `BELLOCODE_OPENCODE_BINARY` after only an executable-bit check. A developer who leaves a test binary override set and then uses the installed CLI unintentionally supplies that binary the live server credential. This requires control of the caller's environment; it is **not** a claim that an ordinary project controls that environment. **Fix:** restrict the override to debug builds and isolated test data roots; refuse to pass a production credential to an unverified executable. Add a release-routing assertion.

### A25 · Minor — Valid CRLF JSONC becomes uneditable in Settings

`Sources/OpenCodeKit/Server/GlobalConfigFolder.swift:109`. **Observed** with the release parser and synthetic input: a valid CRLF file with a line comment returned a syntax error. The scanner compares Swift `Character` against a standalone LF; a CRLF grapheme does not match, so the remainder of the document can be stripped as a comment. **Fix:** tokenize code units or recognize CR, LF and CRLF consistently while preserving offsets. Test the same config under all three line endings.

### A26 · Minor — Resetting the last model key erases an unrelated comment

`Sources/OpenCodeKit/Server/JSONCEditor.swift:128`. **Observed** with the release editor: resetting a final `model` member removed the trailing comment attached to the preceding, retained setting. Removal begins at the previous value's end to consume the comma, thus consuming intervening trivia as well. **Fix:** track comma and member/comment spans separately and remove only the delimiter and selected member. Assert byte preservation of neighboring comments, not just semantic equality of parsed JSON.

### A27 · Minor — Draft restoration does synchronous disk work on the UI actor

`Sources/BelloCodeApp/Launch/AppDelegate.swift:63`, `Sources/ComposerKit/Host/ComposerDraftArchive.swift:149`, `Sources/ComposerKit/Host/ThreadModelComposerHost.swift:126`. The inherited launch task resumes on the UI actor and synchronously enumerates, reads and decodes the draft archive for GC. On a cold thread selection, `loadDraft` also reads the record and probes attachment paths synchronously. Up to 256 records or a slow volume can spoil otherwise cache-first navigation. **Fix:** fetch immutable restoration/retention data off-main, render cached text immediately, and apply only to the same draft generation without overwriting an edit. Measure a cold archive and slow/missing attachments in-process. No latency number was inferred from test counts.

### A28 · Minor — Streaming work is row-bounded, but not proportional to the new bytes

`Sources/TranscriptKit/Transcript/Markdown/MarkdownStream.swift:86`, `Sources/TranscriptKit/Transcript/Controller/TranscriptController+Streaming.swift:125`, `Sources/TranscriptKit/Transcript/Controller/TranscriptController+Streaming.swift:141`. One increasingly long assistant message can repeatedly materialize its UTF-8 buffer on parse updates; the main actor copies the stable block-layout prefix and constructs a new row layout on each applied revision. Stable **rows** need not reparse for total work on one active row to grow quadratically over a stream. **Fix:** keep incremental scan offsets and cached prefix layouts/origins; append or replace only the dirty suffix. Add counters for bytes scanned and stable blocks traversed in a long single-row fixture alongside the existing history-row cost tests. Profile frame times before claiming a threshold violation.

### A29 · Minor — Background model choices claim success on storage or mirror failure

`Sources/Engine/Models/ModelSettingsService.swift:90`, `Sources/Engine/Models/ModelSettingsService.swift:95`, `Sources/Engine/Models/ModelSettingsService.swift:99`. The Git/delegation edits change observable state first, discard SQLite errors and only log a failed plugin mirror write. On a full disk, Settings can say the owner selected a different provider while the next delegated task uses the old one, or a relaunch silently reverts the choice. **Fix:** return an explicit save/apply result to the picker, keep the previous confirmed value or show the pending one, and retry reconciliation. Fault-inject the DB write and the mirror write independently.

### A30 · Suggestion — Retire the parallel reviewer model-token parser

`Sources/Engine/Auto/AutoReviewer.swift:316`, `Sources/Engine/Auto/AutoReviewer.swift:320`, `Tests/EngineTests/AutoReviewerTests.swift:162`. The production Auto caller now passes a typed `ModelSelection`. The old public string overload still splits a token itself and has callers in tests, not production. Its handling of a variant differs from the canonical model-token parser. A future call using the superficially convenient overload can silently turn a variant into part of the model ID. **Fix:** remove the unused overload if API compatibility allows, or implement it exclusively via `ModelSelection(token:)`; move its tests to the shared token grammar with a variant case. This removes a real maintenance fork rather than splitting a file for its size.
