### GV10 and the host git

The fix makes three assumptions about git, checked in its sources. Two hold everywhere: `push.pushOption` set to an
empty value clears the list, and a `url.<base>.insteadOf` rule wins by longest match. The third is new: an empty
`remote.<name>.url` or `.pushurl` clears the list. Upstream git v2.44.0 and v2.45.1 append the empty value; v2.46.0
onwards clear the list. Apple Git-143, -145, -146 and **-154 append**; Apple Git-155 clears. This Mac has Apple Git-157
(git 2.54.0), so the tests and a reading of current sources both look right.

[HostGit.swift:54](../../Sources/ContainerKit/HostGit/HostGit.swift#L54) takes the installed git with no version or
capability check. On Apple Git-154 and older the remote keeps its existing push URLs ahead of the pinned one, so a
`pushurl` written to the repository's configuration between the pre-push comparison and the push is pushed to first.
That is Astra's AF06, a blocker in [their report](v1.0.1-astra-verification-2.md); I did not run an old git and have
not established what it does with the empty entry itself. The finding GV10 reported (settings scoped to the remote
name no longer applied) is closed on every version.

## 4. New findings in the Q merges

### GW02 · blocker · Auto: an abbreviated long option turns the checks on "read-only" commands into no-ops

**Where:** [RiskPolicy.swift:119-127](../../Sources/Engine/Auto/RiskPolicy.swift#L119) (`decide`),
[:906-942](../../Sources/Engine/Auto/RiskPolicy.swift#L906) (`readOnlyShell`) and its option lists at
[:927-931](../../Sources/Engine/Auto/RiskPolicy.swift#L927), [:666](../../Sources/Engine/Auto/RiskPolicy.swift#L666)
and [:234](../../Sources/Engine/Auto/RiskPolicy.swift#L234); `grep`, `sort` and the read-only git subcommands are in
[:871-880](../../Sources/Engine/Auto/RiskPolicy.swift#L871). [RiskPolicyTests.swift:311-312](../../Tests/EngineTests/RiskPolicyTests.swift#L311)
lists the exact spellings the N05 regression covers.

**Problem.** A command with no finding is allowed without the reviewer when `readOnlyShell` says every program in it is
read-only. That depends on lists of exact option spellings: `--open-files-in-pager`, `--ext-diff`, `--output`,
`--recursive`. The programs do not require those spellings. git's `parse-options` and the `getopt_long` of GNU and BSD
utilities accept any unique abbreviation, and none of them is matched.

| Command, in a thread set to Auto | What happens | What the policy intends |
| --- | --- | --- |
| (a) `git grep --op='<command>' needle` | `<command>` runs through `/bin/sh` | N05: `git grep --open-files-in-pager=./x.sh` is refused |
| (b) `printf '…' \| sort --out=.git/config` | writes any file in the project, with chosen content | configuration written by any program is a mandatory escalation |
| (c) `grep --rec KEY .` | reads every file under `.`, `.env` included | a recursive search whose tree holds a secret-looking file is a mandatory escalation |

Each is allowed as "A read-only command inside the project".

**Evidence.** Read and run locally; the app itself was not run.

- The decision path: `findings` finds nothing in (a) (the quoted command is one word; `gitFindings` has no case for
  `grep`), `recursiveSearchFindings` skips a git command, and `readOnlyShell` passes because no argument equals
  `--open-files-in-pager`, starts with `--open-files-in-pager=` or `-O`. For (c), `--rec` falls to the default of the
  option switch, `recursive` stays false, `GrepSearch` returns nil and the preflight is skipped
  ([:270](../../Sources/Engine/Auto/RiskPolicy.swift#L270)). For (b), `writingReadOnlyUse` knows `-o` and `--output`
  only, and the argument's path is examined with `writes: false`, so the configuration file raises nothing
  ([:628-633](../../Sources/Engine/Auto/RiskPolicy.swift#L628), [:483](../../Sources/Engine/Auto/RiskPolicy.swift#L483)).
- git: `parse-options.c` (`parse_long_opt`, v2.47.1) registers a unique abbreviation and uses the text after `=` as
  the value; `builtin/grep.c:417-431` runs the pager with `child.use_shell = 1`. Run here (git 2.54.0, Apple Git-157)
  in a scratch repository: `git grep --op='echo MARKER' needle` printed `MARKER <file>`.
- grep: macOS's BSD grep 2.6.0 searched a tree recursively with `--rec`, `--recur` and `--dir=recurse` (each found the
  match in `.env` and in a subfolder); `--re` was refused as ambiguous. GNU grep resolves long options with
  `getopt_long` as well (not run).
- sort: BSD `sort --out=FILE` wrote the file. GNU likewise (not run).
- Not affected, run here: `rg --pr=./x` is refused as an unrecognized flag; `git diff --ext-d`, `--textc` and
  `--out=` are rejected.
- No test covers an abbreviation, an optional-argument option or `sort --out=`.

**Origin.** Not introduced by these merges. The option list came with the N05 fix (`e331d31`, 1.0.1), and the 1.0.0
Neon review rated the unabbreviated forms Critical (N05). The 1.0.1 release notes state that "Auto's deterministic-allow
and escalation bypasses are closed" ([RELEASE-NOTES.md:155-156](../RELEASE-NOTES.md#L155)).

**Scenario.** A thread is set to Auto. The model, following text planted in a file or a page it read, runs
`git grep --op='sh /tmp/a' -e ''`. No approval card appears, the Auto log records `read_only_command`, and the command
runs in the workspace container with none of the policy's other rules applied to it.

**Why a blocker.** It is the defect N05 was rated Critical for, reached by one spelling the fix did not list, in a mode
whose public description is "Auto never lets a model override its rules" ([USER-GUIDE.md:160](../USER-GUIDE.md#L160)).
Auto is opt-in per thread and the command runs in a container, which bounds the harm but does not change what the
policy promises.

**Fix.** Decide read-only-ness from options the policy knows, not from options it forbids. For `git grep`, `grep` and
`sort` (ideally every read-only program), a `--` argument that is not exactly in a short list of harmless spellings
sends the command to the reviewer; at minimum, match every unique prefix of each guarded option. In the recursive
search preflight, an option that is not exactly known, and `--color` or `--colour` without `=` (Astra's AF14), must
count as "recursion cannot be ruled out". Add (a), (b), (c) and `grep --color -r KEY .` to the N05 regression list,
bump the policy version, and correct the public statements listed under Minor.

### GW01 · major · Dockerfile reader: a line that ends in two escape characters

**Where:** [DockerfileBases.swift:467-472](../../Sources/ContainerKit/Workspace/DockerfileBases.swift#L467)
(`trimContinuation`), joined at [:495-507](../../Sources/ContainerKit/Workspace/DockerfileBases.swift#L495); the second
reading at [:43-71](../../Sources/ContainerKit/Workspace/DockerfileBases.swift#L43) shares it. Called from
[DockerFilterPolicy.swift:765](../../Sources/ContainerKit/DockerFilter/DockerFilterPolicy.swift#L765) and
[DevContainers.swift:210](../../Sources/Engine/Containers/DevContainers.swift#L210).

**Problem.** BuildKit decides with a regular expression built in `setEscapeToken`:
`([^\X])\X[ \t]*$|^\X[ \t]*$`, where `\X` is the escape. A trailing escape continues the line only when the character
before it is not another escape; a run of two or more ends the instruction. The rule is identical in every version
checked, v0.11.6 to `master`, and the classic builder the filtered `/build` route forces imports the same parser
(moby `v28.0.4`, `builder/dockerfile/builder.go`). BelloCode continues on any trailing escape.

```dockerfile
FROM allowed/base:1
RUN echo x \\
FROM disallowed.example.com/image:1
```

BuildKit reads three instructions and pulls the third line's image. BelloCode joins the last two lines into the `RUN`,
in both readings, and returns one image. `buildBaseRefusal` and the dev-container check are the only gates for images
a build pulls, so nothing else refuses it. The same holds under `# escape=\`` with two backticks.

**Evidence.** The regex evaluated mechanically against the Swift rule:

| Line ends in | BuildKit | BelloCode |
| --- | --- | --- |
| one escape | continuation | continuation |
| two escapes | end of instruction | continuation |
| three escapes | end of instruction | continuation |
| a lone escape | continuation | continuation |

[DockerfileBasesTests.swift:158](../../Tests/ContainerKitTests/DockerfileBasesTests.swift#L158) has no such case.

**Origin.** The rule was kept when `bb64816` rewrote the reader for GV01; it predates that commit. Astra reports it as
AF11, major.

**Fix.** In `trimContinuation`, treat a trailing escape as a continuation only when the scalar before it (after the
trailing blanks) is not the escape; or refuse such a line, as the reader already refuses anything it is not sure
Docker reads the same way. Add the three-line file above for `\` and for `` ` ``.
