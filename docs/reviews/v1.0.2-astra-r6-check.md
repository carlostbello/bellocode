## New blocker

**R6-01 · Add Comment loses the user's review text when the composer refuses it.** In one window with a failed draft load, open **Changes → Uncommitted**, select a changed line, type a comment and choose **Add Comment**. This diff reads directly from Git and remains usable while the composer shows Retry. Submission closes the popover and marks the line before asking the composer to add the comment. R6 returns `.draftLoading` even with room for the attachment. The Changes pane reports a capacity error. Reopening Add Comment creates an empty editor, and the gutter mark stores only the file, side and line. The user has no way to recover the comment from either pane. Keep the editor and its text until the composer accepts the attachment, then mark the line and close the editor. [Uncommitted diff](../../Sources/DiffKit/Changes/ChangesModel.swift#L246) · [Comment submission](../../Sources/DiffKit/View/DiffViewController.swift#L647) · [Gutter mark](../../Sources/DiffKit/View/DiffContentView.swift#L33) · [New refusal](../../Sources/ComposerKit/View/ComposerViewController.swift#L473) · [Caller](../../Sources/BelloCodeApp/Content/ChangesSurface.swift#L120)

## Known limitations

- A failed first send can lose its recovery copy if the newly created thread still has no loaded draft after ten minutes. The restore ignores the timeout result, and the host rejects the write. [Wait and restore](../../Sources/ComposerKit/Host/ComposerController.swift#L512) · [Host guard](../../Sources/ComposerKit/Host/ThreadModelComposerHost.swift#L195)
- A follow-up typed in the new-thread editor just before thread creation finishes can miss its debounced save. The project draft is cleared and the outgoing editor can flush to the newly created host before it loads. [Creation](../../Sources/BelloCodeApp/Shell/Seams.swift#L239) · [Host transition](../../Sources/BelloCodeApp/Content/ComposerSurface.swift#L446) · [Save forwarding](../../Sources/BelloCodeApp/Content/ComposerSurface.swift#L417)
